# 交接：剪辑判断的 MCP 工具

待办第二批第 2 条（`docs/01-待办.md`）。方向是王愉超 2026-10-16 定的（决策记录 2.10 末尾）：用户在自己的 agent（Claude Code、Codex、WorkBuddy……彼此并列）里用 FluentFlow 时，剪哪里由这个 agent 判断，用它的订阅；接入靠 FluentFlow 已有的 MCP，不为每种 agent 单独写命令行接入。

## 目标和完成标准

让 agent 通过 MCP 完成「判断剪哪里」这一步，FluentFlow 按它的决定导出、整理处理说明，后面照常写笔记。做完的标准，每条都要能核：

1. 从 agent 提交录像时可以要求「转录完先停下，等 agent 判断」：任务停在一个明确的等待状态，页面和 `get_task` 都说清楚在等 agent，不会自己去找 Claude 或其他模型判断。
2. 有一个工具取判断材料：时间线（带时间的转录稿、每段长空白、画面在不在动），以及画面在动的长空白的截图路径，agent 自己打开看。内容和 FluentFlow 自己判断时给模型的那份一致（同一份 `build_timeline`）。
3. 有一个工具交回决定：保留哪些空白、去掉哪些说话段、各自理由。FluentFlow 收到后套上和自己判断时同样的保护（不剪认出的话、去掉的说话超过 25% 就拒绝），导出一次，生成处理说明，然后照常写笔记（或按 `skip_summary` 停下等 agent 写）。
4. 处理说明里「需要你判断」的条目，agent 能取到、能在对话里问用户，并把回答记进和页面按钮同一处（`verdict`、`flip`、`undo` 已有的路径）。
5. 测试按需求写（每条完成标准至少一条），测试里不连真实模型；ruff、`pylint --errors-only`、全量 pytest 通过。
6. 用一条复制出来的短录像在 Claude Code 里真跑一遍：提交 → 等判断 → 取材料 → 交决定 → 导出 → 处理说明 → 回答一条「需要你判断」。实测记录放 `~/Downloads/FluentFlow测试记录/<时间>-<主题>/`。
7. 决策记录（第二部分「剪气口：哪里剪」）记一条，更新记录写一句用户感觉得到的变化，待办删掉这一条。

## 已核实的事实（2026-10-17）

- **FluentFlow 自己判断的入口**是 `backend/core/survey_cut.py` 的 `survey_and_cut`：它调 `debreath_job.run_debreath(..., revise=revise)`，在 `revise` 回调里做判断，返回改过的剪辑计划，然后导出。判断本身在 `revise_plan`：`build_timeline` 生成时间线，`gap_screenshots` 截图，模型回答经 `parse_answer` 解析，`removal_range` 换算去掉的段，超过 `MAX_SPEECH_SHARE_REMOVED` 就拒绝，`apply_decisions` 落到计划上。之前还有 `spoken_words` / `protect_words` 保护认出的话。（读代码核的）
- **谁来判断**由 `cut_judge.choose()` 决定（Claude → 看图模型 → 文字模型，决策记录 2.10）。`survey_and_cut(chat=...)` 可以传入一个替代的判断者。（读代码核的）
- **笔记那边已经有同样形状的 agent 接入**，照着做：MCP 工具 `get_agent_note_material` / `save_agent_note`（`scripts/fluentflow_mcp_server.py`），对应 HTTP 路由 `/agent/v1/tasks/{task_id}/agent-note/material` 和 `/agent/v1/tasks/{task_id}/agent-note`（`backend/routers/local_agent.py`），逻辑在 `backend/core/agent_note.py`。提交时带 `skip_summary=true` 会记 `note_declined`，任务停在转录稿等 agent 写（`backend/core/media_job.py`）。（读代码核的；Codex 用这两个工具写笔记 2026-10-16 实测跑通，记录在 `~/Downloads/FluentFlow测试记录/2026-10-16-183801-Codex复用kickoff转录/`）
- **工具结果只放一份 JSON 文本**（`_result`，2026-10-17 改），长材料要声明 `_meta["anthropic/maxResultSizeChars"]`，Claude Code 才会整段收下（决策记录 5.19、5.26）。
- **流程编排**在 `backend/routers/local_processing.py` 的 `run_pipeline_then_note`：转录后走 `_cut_and_note_side_by_side`（判断完就把剪辑表交给笔记，和导出同时跑，决策记录 2.14），或在不能同时跑时依次 `_trim_recorded_tail` → `_write_note_after_transcript`。等 agent 判断的任务要在这里分出一条路。
- **处理说明的回答**走 `backend/routers/local_job_debreath.py` 的 `/jobs/{task_id}/cut-report/{ref}/flip`、`/cut-report/verdict`、`/cut-report/changes/{index}/undo`，逻辑是 `survey_cut.flip` / `verdict` / `undo_change`；改判会重新导出，一次只受理一个（决策记录 2.11）。
- **各步只写自己改过的字段**：写任务结果用 `job_store.save_result_changes(task_id, before, after)`，不要用整份写回（决策记录 2.14）。
- **重启本机服务**前先跑 `python3 launchers/macos/count_active_jobs.py http://127.0.0.1:8000`，输出 0 才能重启（AGENTS.md）。它已经把「导出中、笔记待写」算作有任务在跑。

## 还没定的（我的倾向写在后面，动手前跟王愉超确认）

- **等 agent 判断等多久**。倾向：不设超时，页面上写「在等你的 agent 判断剪哪里」，旁边给一个按钮「让 FluentFlow 自己判断」，点了就按现在的顺序找模型。agent 对话关掉了不该让任务永远卡住，但也不该到点就替用户换判断者。
- **怎么要求「等 agent 判断」**。倾向：`submit_local_media` 加一个参数（类似 `skip_summary`），默认不开；不在 agent 里提交的照旧由 FluentFlow 自己判断。
- **截图怎么给**。倾向：照笔记那边给本机路径，agent 自己打开；只给画面在动的长空白，每段两张，和 `gap_screenshots` 一样。
- **agent 交回的决定格式**。倾向：和模型回答同一个 JSON（`keep_gaps` 用时间线里的编号，`remove` 用 from/to 秒数），这样 `revise_plan` 后半段的换算和保护可以原样复用。要先把「解析回答之后」那段从 `revise_plan` 里拆出来。

## 不要走的路

- 不为 Claude Code、Codex 各写一套命令行接入：王愉超定了统一走 MCP。
- 不让 agent 的决定绕过保护（认出的话不剪、去掉的说话不超过 25%、全部放回时以原片收尾）：这些是对所有判断者都成立的规则，不是只防模型的。
- 测试不连真实模型（`tests/conftest.py` 已拦），不提交王愉超文件夹里的原片，只用复制到临时目录的短片段。
- 不发版、不打 tag。功能做完、检查都过了，直接提交推到 main（项目 CLAUDE.md）。
