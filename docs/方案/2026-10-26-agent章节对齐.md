# 章节时间由当前 agent 对齐

2026-10-26 · FluentFlow Local · 王愉超要求「想方案然后去落地做」

用户在 Codex 中请求对齐，就由 Codex 判断；其他 agent 同理。FluentFlow 提供材料、校验并保存
时间表，不启动另一个 agent，不要求 Claude，不改笔记正文、文件、版本或处理记录排序。

## 取舍

采用与 agent 写笔记、判断剪辑一致的「取材料 → 当前 agent 判断 → 交回」方式。
后台启动 Codex CLI 会依赖特定客户端的登录和运行方式；让网页继续自行调用 Claude 也无法满足
当前 agent 完成的目标。网页原有的后台模型入口保留给没有交给 agent 的任务。

## 接口与一致性

- `get_agent_alignment_material`：复用既有章节匹配、标号、带时间的转录稿及提示词。每页最多
  12000 字符，`next_offset` 继续取，同一 `material_version` 贯穿所有页。只对缺少时间的章节标号，
  全文作为上下文，避免仅凭局部找错出处。判断依据是语义，程序只拆页、校验和合并。
- `save_agent_alignment`：接收版本、每个待对齐编号的 `primary` / `others`、实际模型名。
  时间必须有限、在播放文件内、结束晚于开始，章节不能缺少、重复或捏造。复用原有时间表的合并，
  未变的章节保留原来的 ID 和时间。
- 版本覆盖完整笔记、转录稿输入、剪辑与播放时间轴、已有时间表。读后变化返回 409 `stale`；
  保存事务内再比较所有依赖字段，防止最后一刻的并发修改。重取材料，不允许跳过版本。
- 取材料将任务的对齐执行者记为 `agent`；agent 写的笔记也默认由 agent 对齐。页面补齐请求、
  保存监听、队列中的工作都遵守它；已发出的后台请求无法收回，但旧结果不能覆盖 agent 的选择。
  此选择随任务保存、重启后仍在；缺时间时由下一次 agent 会话继续，无付费兜底。
- `get_task` / `get_task_package` 暴露对齐状态，任务包在需要时给出取材料的下一步。
  工具沿用本机 Agent API 的令牌和任务归属检查。服务重启不自动启动 agent。
