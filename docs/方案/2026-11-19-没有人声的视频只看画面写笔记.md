# 没有人声的视频：只看画面写笔记（product-lens 评估）

2026-11-19。起因：王愉超问「转录为空就显示失败，但有的视频本来就没人说话，应该也可以只看画面写笔记吧」。现行规则是决策记录 4.19（2026-11-14 他定）：转录 0 字就判失败，不剪、不写笔记、不做压缩副本。4.19 的起因是 11-09 一份 OBS 录屏只录到静音的麦克风，任务却报完成。

状态：王愉超 2026-11-19 定按改后方案做，已实现，见决策记录 4.21。字幕先用文字识别读出来这一条做成了「画面文字当转录稿」；固定间隔取帧用在读字幕上，写笔记的截图照旧按场景变化加密度兜底取。

## 事实（查过的）

- 任务库里判「没检测到人声」失败的任务一共 2 条，都是 2026-11-19 由 agent 用抖音链接提交的（agent 写笔记、不剪），都约 40 秒：「老袁-像素宝石游戏」「不吃鱼-打击感拆成6层」。
- 两条声音都很响（前者平均 -19.6、后者 -16.3 分贝），是有配乐没人说话的短视频，内容在画面字幕里。
- 4.19 起因那份静音麦克风录屏（11-09 周一会议，前 10 分钟）平均 -44.1 分贝。三条样本里，平均音量把「有配乐」和「静音麦克风」分开了二十多分贝；样本只有三条，门限要再核。
- 提交它们的游戏经验库对话绕开了产品：自己每 2 到 4 秒截一帧拼图读字幕写笔记，并写进了经验库 README。两篇笔记都已写成、质量可用，可以当效果对照。已记进待办「agent 遇到的阻碍」。
- 截帧有「密度兜底」：40 秒视频按最小间隔 2 秒能截到约 20 张，和那边手工的密度相近。本机有苹果自带的文字识别（`frame_text.py`），免费，但现在没接进写笔记这条路。
- 现在的失败说明写「常见原因是录屏时没采到系统声音，或者麦克风是静音的」，对这两条都不对。
- 独立评审另报：一条 25 秒的短片（周冷清）只转出一个数字，按完成收尾，「几乎为空」会从 0 字判断里漏过去（主对话没复核）。

缺的证据：外部标杆没搜（同类工具遇到没人声视频怎么做）；效果没亲眼看；音量门限只有三条样本。

## 改后的方案

1. 先量音量分两种：有声音但没人说话（配乐、音效）→ 照画面写笔记；几乎无声（静音麦克风、没录到声音）→ 保持 4.19 的失败，附「照画面写」按钮。
2. agent 提交的：任务停在等 agent 写笔记，`get_agent_note_material` 在转录为空时返回画面帧和字幕文字。
3. 网页提交的：有声没人说话且不超过时长上限的自动写；其余给按钮。
4. 字幕先用本机文字识别读成带时间的文字，取帧在场景变化之外加固定间隔。
5. 笔记和任务状态写明「依据画面和字幕，视频里没人说话」。
6. 验收：两条抖音视频跑出的笔记，和游戏经验库里两篇手工笔记逐条对；11-09 那份录屏仍然失败。

## 分工

主对话自评 + 一个独立子 agent 评审（只给对象和 skill，不给主对话结论）。评审补出的：agent 模式是主路径、初版会让静音麦克风录屏重新「完成」、文字识别没接进写笔记、时长上限、「几乎为空」那条。主对话补的：11-09 录屏的音量实测（验证了分两种的可行性），待办记录。评审有一处没采纳：它建议的「找外部标杆」这一轮不做，自用阶段收益小。

## 独立评审原文

（原样附录，2026-11-19，子 agent 只读、没改文件）

**一句结论**：方向对，没人声的视频确实该出一份笔记。但这份提案对真实情况判断错了：今天这几条视频不是录音坏了，而是背景放音乐、内容全写在画面字幕里的抖音短片。按提案原样做，横幅里的原因写错了，agent 用户也拿不到东西，11-09 那种麦克风静音的录屏还会重新变成「完成」。

**对象和用户**：主要用户是 agent，它通过 MCP 提交视频，自己写笔记。次要用户是他本人，在网页上提交，由 FluentFlow 自己写笔记。要完成的事：没人声的视频也能得到一份可用的笔记，录坏了的又不会被当成正常结果放过去。

**阶段**：验证有没有用（只有他和他的 agent 在用）。

**我核过的事实**（数据库只读打开）：
- 报「没检测到人声」的任务一共 2 条，都是 11-19 用抖音链接提交的游戏制作短片：老袁 41 秒，不吃鱼 40 秒。两条都是 agent 模式（`intelligence=agent`、`skip_summary=true`、`cut=false`）。
- 两条的原片都有响亮的音轨：平均音量 -19.6 和 -16.3 分贝，峰值都是 -1.5 分贝。也就是有音乐、没人说话，不是没采到声音。
- 第三条（周冷清 25 秒）转出来只有一个数字，任务按「完成」收了尾。也就是说「几乎为空」的情况会从现在的判断里漏过去。
- 游戏经验库那边的 agent 绕开了 FluentFlow：自己用 ffmpeg 每 2 到 4 秒截一帧拼成图，读画面字幕写笔记。笔记质量不错（六层打击感、40 毫秒和 160 毫秒的停顿这类数字都抄对了）。这次绕路没有记进 `docs/01-待办.md` 的「agent 遇到的阻碍」。
- 自动写笔记要用 `claude_vision`，走的是 Anthropic 凭证；agent 写笔记的那条路本来就支持带画面帧的材料。`frame_text`（本机文字识别）不在写笔记这条路上用。

**缺的证据**：外部标杆没有搜（YouTube 自动字幕、Descript、飞书妙记遇到没人声视频怎么做）；用户反应样本只有 3 条且来自同一个对话，上线后记照画面写的笔记被改过几次；这份报告就是独立评审。

**最严重的差距和对提案的改动**：
1. 用测量结果分开两种情况：音轨响但没人声→照画面写、标完成，横幅写「只有音乐或音效，没有人说话，笔记依据画面和字幕写成」；音轨很轻几乎静音→保持 4.19 失败，可附「照画面写」按钮但不自动标完成。分界用 `audio_handler` 已经在量的音量，先拿 11-09 录屏和今天两条核门限。
2. agent 模式是主路径：`get_agent_note_material` 在转录为空时也返回画面帧和字幕文字，任务停在等 agent 写笔记。
3. 字幕是主要内容：本机文字识别先读成带时间的文字，取帧加固定间隔（每 2 到 3 秒）兜底。
4. 网页模式下「有音乐没人声」且不超过上限（比如 10 分钟）的自动写；超过上限或音轨很轻的给按钮。
5. 补记 agent 阻碍；「几乎为空」的门限等第二次出现再定。

**还没验证的**：音量能不能可靠分开两种情况（没量 11-09 录屏）；场景检测在字幕视频上会不会漏帧；一次自动看图写笔记的花费。
