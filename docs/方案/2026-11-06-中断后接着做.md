# 中断后从断的那一步接着做

2026-11-06 · 王愉超要求「处理到一半中断后，能从断点接着做」· 他看过后说「按方案做」，已实现（决策 6.63）

## 要解决什么

任务每一步都做完才算完成。停服务、崩溃、断网、点「停下这一步」之后，从断的那一步接着做：做完的步骤不重做，已经付过钱的模型调用不再付一次。

## 现在是什么样

每个任务有七步（取素材、转录、修正转录稿、剪辑、写笔记、压缩副本、发飞书），每步的状态存在任务库的步骤表里（决策 6.41、6.42）。重启后从第一个没做完的步骤接着做，做完的步骤跳过，这一层已经有了。

问题在**步骤内部**：一步做到一半断了，这一步里已经做完的部分大多丢掉重来。

| 步骤 | 断在中间会怎样 | 花不花钱 |
|---|---|---|
| 取素材（下载链接） | 重启提示框写「原文件不在了，需要重新提交」，其实能重新下载（第 16 处） | 不花 |
| 转录 | 从头转（6.41 的取舍） | 不花，花时间 |
| 修正转录稿 | **停服务要等 165 秒才退出**；点「停下」也要等这一轮做完。已经拿到的模型回答全丢，重启后重新问一遍 | **付两次** |
| 剪辑 | 判断剪哪里的模型调用（判断、判断结尾、整理报告）断在中间的，整套重问；判断完、导出前断的，已经能只重导出（6.42） | 断在判断中：付两次 |
| 写笔记 | 整步重写（6.41 的取舍）。用 Key 写长录像时是一章一章调模型的，断在第五章，前四章重写 | 用 Key：付两次；订阅不按次计费 |
| 压缩副本 | 从头压 | 不花 |
| 发飞书 | 只看「有没有存下飞书回执」：文档已经建好、回执还没存时断了，接着做会再建一篇 | 不花，但会多出一篇重复文档 |

另外三处：

- **「做完」的判定有一个漏洞**：一个步骤还没开始、整条流程因为意外报错提前结束时，这个步骤被记成「跳过」，算做完了。页面上任务显示完成，其实这一步根本没做。
- **第 16 处**：链接和网页上传的任务点「重新提交」后，原来「由 agent 判断剪辑」的选择丢了，改由 FluentFlow 判断；纯转录稿任务卡片上有「重新提交」，点了必定报错。
- **第 18 处**：agent 换个对话接着分段写笔记时，取材料没带分段参数，已经分好的段被悄悄改回整段，存下的各部分对不上。

## 改成什么样

1. **修正转录稿认停止信号。** 这一步的线程改用任务的停止信号（和导出、Claude 命令行同一个），每调一次模型、每读一张字幕图前先看是否已停下；停下时不再等线程池里排着的活做完。目标：停服务几秒内退出，点「停下」几秒内显示已停下。
2. **模型回答按任务存下，接着做时照着用。** 在所有调模型的出口（就是现在记用量的那几处）加一层：每次调用成功后，把回答连同「问的是什么」存进任务库，归到这个任务的这一步。这一步被中断后接着做时，问到同样内容就直接用存下的回答，不再发请求、不再记花费。
   - 一步正常做完、或做失败了，就删掉它存下的回答。所以用户自己点「重写笔记」「重新剪辑」，或因为模型答得不对而失败后「重做这一步」，都会重新问，不会拿旧答案糊弄。只有被停下、被停服务、被崩溃打断的那一步，才照着存下的用。
   - 一举覆盖修正转录稿、剪辑判断、用 Key 写笔记三处，不用每步各写一套续接。
   - 订阅的 Claude 命令行写笔记不走这一层：它是一整段 agent 工作，没法拆成一问一答，而且订阅不按次计费。被打断照旧整步重写。
3. **发飞书先记文档再写内容。** 建好飞书文档就把它的编号存进任务，再往里写；接着做时发现已有编号，更新这一篇（现有的「按章节更新同一篇」那条路），不新建。
4. **没做到的步骤不算做完。** 流程意外结束时，还没开始的步骤记成「没做到」而不是「跳过」，页面显示任务没做完、给「接着做」，接着做从它开始。真正不需要做的（没开飞书、码率低不用压缩）照旧记跳过。
5. **重启时正在下载的链接任务**，提示框里不再说「原文件不在了」，按能重新下载处理。
6. **第 16 处其余两条**：重新提交时带上原来的「谁判断剪辑」；纯转录稿任务不显示「重新提交」。
7. **第 18 处**：取材料时只在明确传了分段参数时才改分段设置，不传就沿用上次的。

**不做**：转录中途接着转（本机转录不花钱，一小时录像重转约几分钟，要做得改转录进程的输出方式，收益小于成本，维持 6.41）；压缩副本中途接着压（同理）。

## 怎么测

- 自动测试：每一处改动配一条最小测试。重点两条：修正转录稿在停止信号发出后几秒内返回；同一步被打断再接着做，模型出口第二次不发请求（假模型记一次调用、接着做后调用次数不变）。
- 实测，全程用假模型（`FLUENTFLOW_FAKE_MODEL=1`，不花钱），素材是复制到临时目录的短片段，任务库也用副本，单独开一个端口，不碰 8000 和他文件夹里的原视频：
  1. 让假模型每次回答慢几秒，在「修正转录稿」进行中按 Ctrl+C 停服务，记下退出用了几秒（目标十秒内，原来 165 秒）。
  2. 重新起服务，同一条任务自动从「修正转录稿」接着做，没有新建任务；查用量记录，停之前已经拿到回答的那几次没有再调用。
  3. 同样的办法在「写笔记」中间停一次（用 Key 的那条路，假模型），看已经写好的章节不再调用。
  4. 点「停下这一步」再点「接着做」走一遍，结果同上。
- 全量测试通过后推 main，同一次提交里更新待办、决策记录、更新记录。
