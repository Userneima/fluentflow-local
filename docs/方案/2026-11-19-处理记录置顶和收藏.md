# 处理记录置顶和收藏

2026-11-19 王愉超提出：agent 替他批量转录的短视频把他要学很久的长视频记录挤到下面，想要置顶，特别好的再加收藏。本文用 product-lens 评估，只有自评，没开独立评审（改动小、可撤回）。

## 对象和用户

处理记录列表（`/agent` 页）和开始页的「最近」6 条。主要用户是王愉超：回来接着学一份长录像的笔记，要在列表里一眼找到它。次要用户是 agent：批量提交短视频，取转录稿自己写笔记，几乎不在页面上打开这些记录。

## 事实（2026-11-19 用 list_tasks 查）

- 11-17 到 11-19 三天新增约 28 条，绝大多数是抖音、B 站的游戏制作和做梗短片，由 agent 批量提交，`has_note` 全为 false（笔记 agent 写在别处，比如游戏制作经验库）。
- 他要长期学的几条（训练营 Week2、黑客级调研两次汇报）已经排到第 29 条以后。开始页「最近」只显示 6 条，早就看不到它们。
- 列表排序：上传中、处理中、排队的在最前，其余按更新时间倒序（`frontend/src/lib/jobMappers.js` 的 `sortJobsForHistoryView`）。筛选只有全部、进行中、待你判断、有问题四档，另有按标题搜索。
- 现在没有任何置顶、收藏、归档、隐藏字段。
- agent 从链接提交的任务在 metadata 里带 `agent_input_type`，能和页面上手动提交的区分；本地文件提交是否也带，未核。

## 判断

价值：拿三种做法比。

| 做法 | 解决挤下去吗 | 他要付出的 | 问题 |
|---|---|---|---|
| 不做，靠搜标题 | 能找到，但每次都要想起标题再搜 | 每次几秒 | 开始页「最近」永远看不到长视频 |
| 置顶 | 解决，置顶的永远在最前 | 每条长视频点一次，学完取消一次 | 学完忘了取消，置顶区会慢慢变长 |
| 按来源分开（agent 提交的不进主列表，或加一档筛选） | 从根上解决，挤他的那批本来就不是给他看的 | 零操作 | 把东西藏起来要说清楚，否则会以为任务丢了 |

置顶是他点名要的，成本小，先做。按来源分开是更根本的解法，但会改变列表默认显示什么，放第二步，他点头再做。

收藏和置顶看起来像，用途不同：置顶是「正在学」，学完就取消；收藏是「值得以后回看」，长期留着。我倾向这一轮只做置顶，收藏先不做：列表现在一百多条、能按标题搜，找回一条好的还不难；卡片上并排两个相近的标记，每次都要想该点哪个。等他真遇到「记得有条很好的但搜不到」时再加，那时改成一档「收藏」筛选即可。这条由他定。

## 缺的证据

- 外面的标杆：只凭已知产品举例，没搜原文。置顶是成熟做法，不值得再搜。
