# 先通查原片，再按剪辑地图剪（讨论中）

状态：讨论中，未定稿，不按这份动手。2026-10-15 王愉超提出。

## 想解决的问题

现在剪气口时只知道音量，不知道录像讲了什么。会后多录的尾巴、被检测成人声的环境音、无声但画面关键的片段，都要读懂内容才能判断。现在只能事后补救：剪完、转录完再裁结尾（决策记录 2.6），同一个视频改两次。

## 现在的流程（2026-10-15）

1. 找空白、剪空白：只看音量，拿不准的逐处量，夹在空白里的短碎片用人声检测器判断（决策记录 2.1、2.5、2.7）。
2. 导出剪后视频：本机有硬件编码器就用硬件编码（3.10）。
3. 转录剪后视频：字幕时间天然对得上剪后视频。
4. 裁结尾：模型读转录稿判断会在哪里结束，剪后视频和转录一起截短（2.6）。
5. Claude 看剪后视频的画面和转录稿写笔记，查漏，整理进产出文件夹。

## 讨论中的新流程：先通查原片，画出剪辑地图，再只导出一次

换顺序的目的（王愉超，2026-10-15）：动手剪之前先把原片通查一遍，知道哪里该去、哪里该留，尤其是无声但画面关键的片段。转录只是通查要用的材料之一。

1. 程序量出能量化的（不剪任何东西）：
   - 声音：哪里安静、多安静，哪里检测到人声，哪里是持续的环境噪音；
   - 画面：哪里在变（滚动、打字、翻页、切窗口），哪里静止；
   - 文字：转录原片，每句话的时间。
2. Claude 或用户自己的 agent 读这条合在一起的时间线，按上下文给出剪辑地图：每一段标"去除"或"保留"，写明理由。例：
   - "大家看一下这页 PPT"之后安静、画面停在 PPT 上 → 保留，是给观众读的时间；
   - "我来演示一下"之后安静、画面在动 → 保留；
   - "稍等我连一下""能听到吗"之后的安静 → 去除；
   - 检测到"人声"但转录里没有有意义的字 → 环境音，去除；
   - 会后多录的尾巴、整句重复的废话 → 去除；
   - 普通气口停顿 → 去除。
3. FluentFlow 检查地图（原片不动、不许剪掉太多说话），只导出一次视频。
4. 把字幕时间换算到剪后视频上。
5. 写笔记、查漏、整理文件夹，和现在一样。

分工：机械的测量、导出、核对由程序做；要读懂内容的判断交给模型。模型不逐个判断几千处空白：程序先处理明显的，只把拿不准的成片、内容层面的问题和"无声但画面在变"的片段交给模型。

控制成本：两小时的转录稿约四万字，可以整份给；画面只给"无声但画面在变"的片段各截几帧，不给整段视频。

## 截图

通查沿用产品现有的两种截图方式，不另起一套：

- 画面明显变化时截一张（PPT 换页、切窗口）。实测 15 分钟会议 79 张不重复画面，69 分钟课 97 张，约一小时一百张。
- 文本模型读转录稿，提出哪里需要截图（最多 8 处），再由模型从该时间段的候选帧里挑一张。

两种一起用：最有用的截图常常是转录稿没提到的（端口号、目录页、被转录听错的模型名），演示操作时讲者也常不说话，所以换页截图保证不漏，读字幕截图负责找准位置。

截图按用途分开：

- 判断剪不剪：只看"无声但画面在变"的片段，每段几帧（周二会议只有 4 段）。
- 写笔记配图：换页截图加读字幕截图，最后由模型挑出真正放进笔记的几张。

量在模型承受范围内（2026-10-15 查 Claude 官方文档）：一次请求最多 600 张图，超过 20 张时每张长边不超过 2000 像素；一张 1080p 约 2700 个视觉单位，上下文约放得下三百多张；约 1 美分一张。张数再多时先拼成缩略图墙粗看，再对挑中的看原图。

裁剪：模型说要哪块区域（例：只留共享屏幕，去掉参会人头像栏），程序找准边界再裁。模型给的框位置是大概的，不直接用它的坐标。

字词级的重复（"那那那"）不剪：转录的逐字时间会偏几百毫秒，剪口落不准（决策记录 2.4）；只去整句。

## 代价

- 字幕时间要换算：转录的是原片，剪掉空白后每句话都要按"它前面一共剪掉了多少"往前挪；一句话横跨一处剪口要缩短；剪口不能切进半个字。当初选先剪后转录就是为了省掉换算。缓解：产品已有换算代码，一句话横跨剪口时按剪口缩短；导出后抽查几句字幕的位置。
- 转录对原片做。转录前人声检测器会跳过没人说话的部分，所以要转的说话量和转剪后视频差不多。
- 每条多一次模型调用（约一两分钟），短视频可以跳过。

## 已定（王愉超，2026-10-15）

- 剪辑地图不给用户看、不让改，由模型默认执行。界面复杂度太高。
- 高风险的几处在整个任务完成后告诉用户，请他确认，例："我剪掉了原片 13:52 之后的 24 分钟，判断是会后多录的，你确认一下是不是有这么大段的空白。"时间用原片的时间。
- 页面样机（分支 `mock/cut-confirm`，网址加 `?mock=cut-confirm`）：任务卡片上一块"有 N 处剪得比较多，请确认"，每条写原片时间、剪掉多长、理由，三个按钮："在原片里听这段""剪得对""这段不该剪"。"剪得对"收成一行、可撤回；全部答完整块变灰。两种回答都记下来，用来检验模型判断准不准、给案例库当素材。主路仍是 agent 对话，页面是给不用 agent 的人。
- 只有剪和留两种处理，不做加速播放：要加速不如直接删；决定保留的，原样保留多长就多长。
- 中间的废话也去掉（调设备和确认声音、整句重说、和主题无关的对话），开头的等待、结尾多录的部分同样去掉；去掉的每一段都列给用户确认，不限条数。
- 有人说话的地方一律不剪，用户不用再确认这一类。"有人说话"要两边都认：转录在这一句的时间里认出了话，人声检测器也在剪口里听到了声音。只看转录不够：实测 8 分钟会议里，只看转录会多留 37.8 秒，其中检测器只听到 2 到 6.5 秒人声，其余是切成 122 个碎片的安静（2026-10-15）。
- 转录不记每个字的时间：2 小时 28 分的百校会议上，用整句时间加检测器保住 165.1 秒，用逐字时间保住 160.5 秒（全部包含在前者里），而记逐字时间会让转录变慢：之前单独测过慢 18% 到 40%；2026-10-15 在百校的一段 10 分钟上各跑两次，不记 195 秒、264 秒，记 391 秒、271 秒（当时另有渲染任务在跑，数字波动大，方向一致）。
- 转录在没人讲话的噪音里会凭空写出外语句子（"感谢观看""请订阅点赞"之类）。中文录像里和全片文字不同的句子会标给模型，当作没人讲话来判断和写理由；处理说明不把它们当"说的是"引用。
- 撤销：每条旁边一个"这段不该剪"，点了按保留这段重新导出一次，模型的其他决定照旧，不重新转录，笔记按新版本重写；用 agent 的用户直接对 agent 说。

## 实现（分支 feat/survey-first，未合入主线）

- 先转录原片，再剪：程序找空白，剪口避开有人说话的地方；3 秒以上的空白连同前后的话、画面有没有在变，交给模型判断留不留；模型同时列出要去掉的有人说话的段落。
- 模型要去掉的说话超过全部说话的四分之一时，这些去除整体不执行，空白的判断照旧。
- 判断用设置里的文本模型，没有就用 Claude；都没有时只按音量剪，转录出字的地方照样不剪。剪辑判断和写笔记是两次调用：判断只读文字，写笔记看剪后视频的画面。
- 只导出一次，字幕时间换算到剪后视频上，之后的笔记、文件夹整理和原来一样。
- 任务卡片上列出待确认的剪辑，三个按钮都可用。
- 2026-10-15 用 9.1 运营会议的复制品（8 分钟）跑通整条流程，包括"这段不该剪"。

## 处理说明（已做，分支 feat/survey-first）

每条剪过的视频在任务卡片上有一份处理说明，让用户感知产品做了什么，也能纠正。

- 程序列出每件事实，带原片时间：3 秒以下的短停顿合成一条，每段长空白（剪掉，或因画面重要而保留），每段去掉的有人说话的内容，每处保住的轻声说话。模型负责分组、起标题、决定展开还是折叠、每条写一句理由；它只能按编号引用，时间一律用程序量的，漏掉的条目自动收进最后一组"其他处理"。没有模型时按种类分组。
- 由很多处合成的条目（短停顿、其余轻声说话）是产品默认做对的事，只陈述事实，不放按钮，用程序的固定说法。
- 一处剪辑只列一次：和一段被去掉的说话连在一起剪的空白，算作那段说话的一部分。
- 只问两类，放在最上面一组"需要你判断"：Claude 自己标了拿不准的（写明拿不准在哪），和规则规定必须问的（去掉的有人说话的内容、单独超过 1 分钟的剪辑、模型想去掉但被程序拦下的）。这一组每条默认收成一行，点开才有细节和按钮。其余各组只呈现 Claude 的说明和"在原片里听"，另有不起眼的"改成保留 / 改成剪掉"。
- 按钮：剪掉的条目"剪得对 / 这段不该剪"，保留的条目"确实该保留 / 这段应该剪掉"。"剪得对 / 确实该保留"立即记下，这一条移到折叠的"你已确认的"里，可撤回；没点的算没看过。会改动视频的按钮先确认（要重新导出、重写笔记），再执行。
- 回收箱"你改过的地方"：每一处改动都记着原来的判断和理由，过多久都能撤销；撤销是按原来的判断重新导出，不存旧视频文件（每份几十到几百 MB）。
- 任务卡片上入口显示"有 N 处需要你判断"，判断完显示"看看这条视频处理了什么"。
- 修展示上的问题只重新整理处理说明，不重新判断、不重新导出、不重写笔记。

## 意外情况（已做，2026-10-15）

- 原片被挪走：要重新导出或"在原片里听"时，先在原位置找，找不到就按文件名在电脑里搜（Spotlight），找到且时长和处理时一致就接上，任务记住新位置。
- 原片被换成同名的另一个文件：时长和处理时对不上就拒绝重新导出，说清两个时长，请用户把原来那份放回去；按旧决定剪新文件会剪错地方。
- 原片删了或移动硬盘没插：重新导出前明确告诉用户原来在哪、怎么做；"在原片里听"改放任务里存的原片声音（没有画面）。
- 产出文件夹被改名：按文件夹里的隐藏标记找回，继续更新；被挪到别处：不在原位置重新建一个，提示用户挪回来，最新结果仍在 FluentFlow 里。
- 重新导出失败，或服务在导出中途重启：把剪辑决定、转录稿的时间放回导出前的样子，剪后视频还是原来那份，提示"可以再点一次"；服务启动时自动处理上次没导完的。
- 链接下载的视频过了保留期被 FluentFlow 清掉：以 `~/Movies/FluentFlow/` 里那份为原片（主线）。

## 用户的反馈让以后要问的越来越少（2026-10-15 王愉超定）

处理说明里只有 Claude 拿不准的、和规则规定必须问的条目才请用户判断。用户的每次判断都要让以后的判断更准，需要问的越来越少，直到不用问。只有用户明确点过的才算反馈，没点的算没看过。案例和规则只存在用户本机。

1. 用户的判断作为下一次的参考案例：每次"剪得对 / 确实该保留"和每处改动，连同当时的情况（前后的话、画面在不在变、多长）和 Claude 原来的判断，交给下一次剪辑和整理说明的模型；哪些案例和眼前相似由模型判断。（已做，分支 feat/survey-first）
2. 规则规定必须问的类别（去掉的有人说话内容、超过 1 分钟的空白）设毕业条件：用户连续确认一定次数、其间没改过，这一类就不再单独问，只写进说明；之后改了一次就重新问。次数门槛等积累了真实点击再定。
3. 用户反复纠正同一类时，起草一条剪辑规则请他确认一次，写进他自己的剪辑规则，做法和笔记规则一样。

## 案例库

- 把实测中遇到的情况写成案例（什么情况、怎么判断、依据），放进随产品附带的 agent skill，给模型和 agent 参考。起点：会后多录的尾巴、键盘鼠标声、背景人声、拿不准的空白。
- 用户投稿：经 GitHub 模板提交，只描述情况和做法，不带录像；人工审核后才收进随产品发布的案例集（agent 会照案例做事，未经审核的投稿等于给所有用户的 agent 下指令）。

## 还在讨论

- 无声但画面关键的片段（讲者不说话在演示、滚动文档、写代码、写白板）怎么识别、剪还是留。
  - 实测周二会议：1.5 秒以上被剪的空白 24 段，画面在变的 4 段共 38 秒；最长 31 秒在会议开头（等人、切窗口、开录屏软件），剪掉是对的。
  - 发现靠程序（已有测画面变化的代码），判断是不是关键内容要交给 Claude 看几帧截图；程序分不出"切窗口"和"默默演示"。
  - 没有模型时的默认倾向：画面持续在变、超过 3 秒的无声片段先保留；代价是会议开头那类片段也会留下。
  - 优先级取决于用户的录像以课程教程为主还是会议为主，待王愉超答复。
