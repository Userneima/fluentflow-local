# 先转录，再由模型或 agent 定怎么剪（讨论中）

状态：讨论中，未定稿，不按这份动手。2026-10-15 王愉超提出。

## 想解决的问题

现在剪气口时只知道音量，不知道录像讲了什么。会后多录的尾巴、被检测成人声的环境音、无声但画面关键的片段，都要读懂内容才能判断。现在只能事后补救：剪完、转录完再裁结尾（决策记录 2.6），同一个视频改两次。

## 现在的流程（2026-10-15）

1. 找空白、剪空白：只看音量，拿不准的逐处量，夹在空白里的短碎片用人声检测器判断（决策记录 2.1、2.5、2.7）。
2. 导出剪后视频：本机有硬件编码器就用硬件编码（3.10）。
3. 转录剪后视频：字幕时间天然对得上剪后视频。
4. 裁结尾：模型读转录稿判断会在哪里结束，剪后视频和转录一起截短（2.6）。
5. Claude 看剪后视频的画面和转录稿写笔记，查漏，整理进产出文件夹。

## 讨论中的新流程

1. 转录原片；同时程序把候选空白都量出来（多安静、哪些碎片被检测成人声、哪些空白期间画面在变），这一步不剪。
2. Claude 或用户自己的 agent 读转录稿和这份测量，给出剪辑建议：正式内容在哪里开始和结束、哪段跑题、哪些"人声"其实是环境音、哪些空白有意义要留。
3. FluentFlow 检查建议（原片不动、不许剪掉太多说话），只导出一次视频。
4. 把字幕时间换算到剪后视频上。
5. 写笔记、查漏、整理文件夹，和现在一样。

分工：机械的事（找空白、导出、核对）程序做；要读懂内容的判断交给模型。模型不逐个判断几千处空白，只判断程序标出来的成片拿不准的地方和内容层面的问题。

## 代价

- 字幕时间要换算：转录的是原片，剪掉空白后每句话都要按"它前面一共剪掉了多少"往前挪；一句话横跨一处剪口要缩短；剪口不能切进半个字。当初选先剪后转录就是为了省掉换算。缓解：产品已有换算代码；转录给出每个字的时间，剪口只落在字和字之间；导出后抽查几句字幕的位置。
- 转录对原片做，比剪后视频长，慢多少要实测。
- 每条多一次模型调用（约一两分钟），短视频可以跳过。

## 已有倾向（待确认）

- 剪辑建议默认直接执行，不停下来等确认；原片始终在，任务里写清剪了什么、为什么，可以按"不剪这一段"重新导出。
- 剪辑建议和写笔记分两次调用：建议只读文字，写笔记要看剪后视频的画面。
- 没有 Claude 也没有 agent 时，退回纯音量规则。

## 案例库

- 把实测中遇到的情况写成案例（什么情况、怎么判断、依据），放进随产品附带的 agent skill，给模型和 agent 参考。起点：会后多录的尾巴、键盘鼠标声、背景人声、拿不准的空白。
- 用户投稿：经 GitHub 模板提交，只描述情况和做法，不带录像；人工审核后才收进随产品发布的案例集（agent 会照案例做事，未经审核的投稿等于给所有用户的 agent 下指令）。
