## 现在是什么样

写笔记有三条路：Claude 结合画面写、用户自己的 agent 写、文字模型（通义千问、DeepSeek、Kimi、MiMo、OpenAI）只按转录稿写。前两条读同一份写法：`backend/note_skills/fluentflow-note-default/SKILL.md`，加上用户自己那份（`apply_note_rule` 加的规则写在里面），再加校正文档。文字模型读的是另一套：`backend/core/ai_prompts.py` 里的固定提示词。写法改动只进了 skill，文字模型那套没跟上，于是：

## 合并后长什么样

1. **写法只有一份**：skill（默认那份 + 用户自己那份）加校正文档，三条路都读。文字模型多读一小段「你看不到画面」的附加说明：不引用截图，画面上才有的内容不写，其余照 skill。`ai_prompts.py` 里讲「怎么写笔记」的那些段落删掉，只留按章写的结构说明（这一章写哪段、统稿时合并重复）。
2. **给文字模型拼提示词只在一处**：新函数 `note_prompt.for_text_model(task_id)`，返回 skill + 用户规则 + 校正文档 + 说话人说明 + 「看不到画面」附加段。首次写、按章写的逐章和统稿、查漏补写、网页重写、agent 重写、`draft_note_part` 都调它，不各拼一遍。按 `AGENTS.md` 的规矩登记进「什么在哪决定」，配测试守住。
3. **重写带上同样的材料**：网页和 agent 的「按文字重写」从任务里取带说话人标号的转录稿（和首次写同一个来源），不再用前端传来的纯文本。
4. **「没看画面」一个标记**：文字模型写的笔记（首次、重写都算）一律记成 `text_fallback`；md、PDF、飞书那份开头加一行「这篇由文字模型按转录稿写，没看画面」。笔记换成 Claude 或 agent 写的之后这行自动消失。
5. **改判后文字模型重写**：先把当前笔记存成可恢复的旧版（和 Claude 那条路一样调 `record_replaced_note`）；没有 Key 写不了时，笔记照旧留着，处理说明里写明「这篇笔记对应改判前的剪辑」，并给交给 agent 写的那段话。
6. **`draft_note_part` 用实际写笔记的模型**：任务的笔记是谁写的就用谁验证规则；没有任何模型时照旧报错并说明。

## 影响哪几条路径

- 处理完自动写笔记：`local_intake_flow._write_text_note_instead`、`media_job` 里旧流程的文字笔记
- 长录像按章写：`ai_summarizer._run_chapter_coverage_mode`
- 网页「重写笔记 → 按文字重写」：`local_note_regen`、前端 `editor.jsx`
- agent `regenerate_note`：`local_agent`
- 改判后重写：`local_job_debreath` → `write_note`
- 规则验证：`note_feedback.draft_note_part`
- 「代写」标记：`output_folder`、`note_pdf`、`feishu_markdown` / `lark_exporter`、前端 `noteWriter.js`

Claude 和 agent 两条路的写法不变，它们读的 skill 文本一个字不动。

## 怎么测

- **流程**（假模型，不花钱）：替身模型记下收到的提示词。断言六个入口拿到的提示词相同，里面有用户加的一条规则、校正文档里的一个名字、说话人标号、「（存疑）」要求和会议「还没定的」；`test_where_things_are_decided.py` 里登记，别处再拼提示词就报错。另测：改判后重写留下可恢复的旧版；md、PDF、飞书那份开头有「没看画面」那行。
- **效果**（真模型，要花钱，先等你点头）：用 `scripts/evaluate_note_quality.py --compare-skills` 在质量考题上并排比新旧两版，两条录像：一场一小时以上的会议（看决定、待办、还没定的、人名）、一节课（看术语和「（存疑）」）。用通义千问 `qwen-plus`，按量计费的 Key，估计两条加起来几块钱以内，跑一次。新版不比旧版差才合进 main。
