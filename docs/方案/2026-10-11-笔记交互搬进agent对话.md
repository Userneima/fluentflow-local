# 笔记交互搬进 agent 对话（2026-10-11 定）

> 历史方案。确认方式、验证轻重和设置页撤回已由 [决策 5.38](../02-决策记录.md#538-个人写法由-agent-提议用户确认设置只查看和撤回) 更新；当前执行规则见 `agent/skills/fluentflow/SKILL.md`。

## 分工

- **界面保留，给人查看**：历史记录、设置页、「我的笔记风格」里 skill 的具体内容和每条规则的来历。
- **阅读**：笔记导出成 PDF，或导出到飞书去读。
- **反馈**：看到不满意的地方，截图发给自己的 agent，说一句哪里不对。
- **写笔记、改写法**：由 agent 在对话里完成。

## 反馈流程

1. 用户截图指出问题。agent 先把这篇笔记改好，这一步每次都做。
2. agent 判断这是一次性的（某个人名写错），还是会反复出现的写法问题。一次性的到此为止。
3. 写法问题由 agent 自己验证：起草一条规则，用新规则把这段录像出问题的那一部分重写几遍（同一段多跑几次，排除碰巧写对），检查这个问题还在不在、其他地方有没有变差；不通过就改规则再跑，几轮后通过才写进用户的 skill。
4. 写进去之后告诉用户一句「加了一条规则：……」。界面「我的笔记风格」里能看到这条规则、它来自哪次反馈、验证了几轮，可以退回。
5. 同一个问题用户再次提出，说明规则没管用，这时才请用户参与：给他看规则怎么写的、新旧两版对比，一起定怎么改。

三条保障：

- **检查的人和写的人分开**：「问题还在不在」交给一个没参与写的检查者判断，只答在或不在，允许答判断不了。
- **每条反馈都留成一个测试用例**：录像那一段的转录快照、用户指出的问题、怎么算改好。以后任何规则改动都把旧用例重跑一遍，防止把修好的问题改回来。这些用例就是笔记测评集的一部分。
- **只重写出问题的那一部分**，不整篇重写，验证花的额度和时间都按这一段算。

这取代了 2026-10-09 笔记 skill 计划里「每条候选规则经用户确认后才写进去、生效前并排给用户看」的做法；用户只在同一问题复发时参与。

## 要做的事

1. **agent 改写法用的工具**（MCP）：读当前的笔记写法；用候选写法把某个任务的某一部分写一份但不保存（产品自己写笔记时用，agent 自己写笔记时它直接按候选写法写）；记一条反馈并存成测试用例；把验证通过的规则写进用户的 skill，同时记下来源反馈和验证结果；查某个问题以前有没有被提过。
2. **界面「我的笔记风格」**：显示每条规则的来历（哪次反馈、哪天、验证了几轮）和退回入口。
3. **导出 PDF**。
4. **打包成 agent 插件**：MCP 服务加一份写给 agent 的 skill，写明拿到视频怎么处理、收到截图反馈怎么走上面的流程；一条命令安装时一起装好。
