# 边看边改转录稿的体验评估

2026-11-19 · 按 product-lens 评估，起因是王愉超反馈「修改了转录的原文之后转录稿跟随会断掉」。动作做到哪见最后「动作状态」。

## 对象和用户

编辑页上一边放录像一边改转录原文的流程。用户是王愉超本人，每天看一到三小时的课程录像，边看边把听错的名字和术语改掉。改转录稿是提高笔记质量的手段：笔记、字幕、跟随播放都以转录稿为来源（决策 4.10）。阶段：只有他一个人在用，在验证有没有用。

## 事实（读代码、查文档得到，未在页面上实测）

- 点进任何一句话改字，页面会关掉「转录稿跟随」：文本校对模式是 `editor.jsx` 的 `focusSentence`，视频复查模式是 `stopFollowing`。离开这句话、重新点播放都不会恢复跟随，只能点标题栏的开关，或者点时间重新接上。
- 「点进句子就停止跟随」从第一版就是这样。决策 6.51 加了「手动滚动也停止跟随」，但没有规定什么时候自动恢复。测试里没有「改完字以后还跟不跟」这一条。
- 文本校对模式里每段只有段首一个时间。点这个时间会退回到段首，可能退几十秒。功能提示（`featureHints.js`）写的是「点任意一句的时间，就接着跟」，在这个模式里做不到。
- 光标停在文字里时，没有快捷键能暂停、播放或往回退，只能用鼠标点播放器。
- 两种模式不一致：文本校对里，没在播放时点进一句，播放位置会跳到这一句；视频复查里不会跳。
- 笔记那边是同一个问题：在笔记里按键，笔记跟随也会停（`NoteEditor.jsx`）。

## 外部做法

| 工具 | 做法 | 出处和档 |
|---|---|---|
| Descript | 手动滚动后停止自动滚动，点「回到播放处」或按 Esc 恢复；每次重新播放也会自动恢复跟随 | [帮助文档](https://help.descript.com/descript-tour/playback-and-navigation.md)、[更新记录](https://feedback.descript.com/changelog/resume-autoscrolling)，有出处未核原文 |
| AutoEdit 3 | 打字时自动暂停播放，停手后接着播放；滚动同步可以开关 | [使用手册](https://autoedit.gitbook.io/autoedit-3-user-manual/1.0.11/transcriptions/correct-the-text-of-a-transcription)，独立评审已核原文 |
| oTranscribe | 打字时按 Esc 暂停或播放，F1、F2 后退或前进 | [GitHub](https://github.com/adifah/oTranscribe)，有出处未核原文 |
| Microsoft Stream（旧版） | 编辑时转录稿不停跳回播放处，被用户当成 bug 反馈，官方承认 | [论坛](https://techcommunity.microsoft.com/discussions/streamforum/cant-turn-off-auto-scroll-while-editing-transcript-of-stream/1598916)，有出处未核原文 |

从这几家能看出：改字时不该把人拉走（FluentFlow 已经做到），但停掉的跟随要能自动接回，并且手不离开键盘就能控制播放。

缺的证据有两类：
- 缺「亲眼看一次」：在 8000 上拿一节长课录像，走一遍「暂停、改字、播放」，看跟随有没有断。

## 动作（按先后）

1. **离开这句话就自动接回跟随**：点进去之前在跟随的，离开时恢复，等换到下一句再滚动过去，改字的过程中仍然不滚动。笔记跟随同样处理。
2. **光标在文字里也能控制播放**：Esc 播放或暂停，另加一个键往回退 3 秒。「打字时自动暂停」先不做，用过 1、2 之后再看要不要。
3. **提示和开关改准**：两种模式分别写准确的提示；跟随停下后，开关显示成「回到播放处」。
4. **两种模式统一**：点进一句话时，要么两种模式都把播放位置跳过去，要么都不跳。
5. **补测试**：改字、离开这句话、换句以后，转录稿会滚过去。

我自评和一个没看过我结论的独立评审 agent 各查了一遍，两边都查出了根因、体验差距和外部做法。

- 只有独立评审查出的：两种模式点进句子时行为不一致（第 4 条）；笔记跟随有同样的问题；测试缺口（第 5 条）；AutoEdit 原文的核对。
- 我先查出的：段落视图点时间会退回段首、提示文案做不到，独立评审也查出了这一条。
