# 七、安装

决策记录的一节，写法见 [决策记录](../02-决策记录.md)。

**现状**（2026-11-27 按决策条目核对，含 7.7 到 7.15）

- 目标：用户把仓库链接交给自己的 agent 说「帮我装上」，之后不输密码、不点系统弹窗、不申请 API Key（7.1）。写给 agent 的安装说明是仓库根目录的 `AGENT_INSTALL.md`（安装、更新、起停服务、卸载）；需要人出面的只有四种：磁盘不够、网络不通、Windows 上镜像和 winget 都装不上 Python 或 FFmpeg、链接要登录。
- macOS 一条命令装（`install.sh`）：从 Releases（GitHub 慢就从 npmmirror）下载最新版到 `~/fluentflow-local`，不用 git；没给位置、默认位置又没装过时，先问正在运行的服务装在哪，更新那一份（7.12）。缺 FFmpeg 时下载免安装版放进数据目录（这个地址没有国内镜像，也不校验，7.13）；界面用发版时构建好的（7.8）；Python 只用 3.10 到 3.14，挑本机合格的里最新的，没有就用 uv 装 3.12；比 3.14 新的旧虚拟环境删掉重建（7.5）。依赖用 uv 按锁定文件装。不用 Homebrew、不要密码。每样下载先探原站，慢就走国内镜像（7.7）。再运行一次就原地更新到最新发布版，失败换回旧版（7.9）；更新被打断后下次运行把旧版连同它的 `.env` 放回原位，写了一半的拷贝会说明是它留下的、不当成用户的文件夹删掉（7.12、7.14）。更新开始前在安装文件夹旁边**一步建出** `<安装文件夹>.fluentflow-updating`（两个更新同时进来只有一个能建出来，另一个停在使用前；建过标记的才删它），每次退出都删掉，让别的 agent 的 MCP 服务不要在换代码、重建环境时起服务（7.14）。
- 装完自动完成：生成访问令牌写进 `.env`，下载 sherpa-onnx 说话人模型（失败只提示，见 4.1），转录模型放到后台下载（7.8），启动服务（端口 8000），在 Claude Code、Codex 和 OpenCode（装了才写）里注册 MCP 工具（端口不是 8000 时三处都带上地址，7.15）、装随产品的 agent skill，跑 MCP 自检，在桌面放「FluentFlow Local」图标（Windows 另有「停止 FluentFlow Local」）。已注册的条目指向这一份或另一份还在的安装就不动，指向的文件已经不在就重新注册；Codex 的配置和 skill 按 `CODEX_HOME` 找（7.13）。数据目录、模型位置可以写在代码目录的 `.env` 里，服务和所有脚本按同一规则读（7.7）。卸载会注销 MCP 工具（按它注册时的作用域），连更新失败留下的那份和安装时的下载缓存一起删（7.7、7.10、7.13）。更新和卸载判断数据、下载、模型在不在代码目录里时，照服务的读法定位置，读不准的当作在里面；安装时数据目录、模型位置和下载缓存也照服务的读法换成完整路径，读不准就停下说明、什么都不装；删数据只整个删全是 FluentFlow 东西的数据目录，否则只删它自己的、列出留下的（没有别的可删时也列，7.13）；用户自己复制出来的代码文件夹不当成更新留下的（7.11）；路径里的链接和 `..` 按系统打开时的实际目录算（7.12）。
- 每次启动先自检，再在后台检查 yt-dlp 更新，每天最多升级一次，同一时间只跑一个；升级那几秒里开始的链接下载等升级做完再试（7.2）。
- 端口在启动器、卸载脚本、后端都按「环境变量 → 仓库 `.env` → 8000」读（7.2）。
- Windows 一条命令安装是 `install.ps1`（提示用英文），整个产品装进选定盘上的一个 `FluentFlow` 文件夹（7.7）；文件夹里的数据、模型、下载和缓存写成跟着文件夹走的引用（`${FLUENTFLOW_HOME}\…`），整个文件夹挪到别的盘以后，下次安装或双击桌面图标时 `.env` 改指新位置（旧位置的盘符/卷还在、只有文件夹不在时才算挪动；盘没接上时原样留着并说一句），旧布局的 pip/uv/npm 缓存也改放进数据目录，`.env` 的改动写成临时文件再整体替换（7.12、7.13、7.14）。FFmpeg 先从国内镜像下载进数据目录的 `bin`，连不上再用 winget（7.6）；Python 按 3.12、3.13、3.11、3.14、3.10 的顺序问 `py.exe`，都没有就下载官方安装包给当前用户装 3.12（7.7）；依赖按 Windows 锁定文件用 uv 装（7.9）；检测到 NVIDIA 显卡时装项目自带的 CUDA 运行库。服务在后台运行，不占窗口；虚拟环境坏了启动器自己重建（7.9）。换文件夹时挪不动会重试三次（7.12）。安装、启动器和 MCP 服务都按 UTF-8 收发，Windows 脚本带 UTF-8 标记、提示用中文（7.2、7.4、7.5）。
- 有新版本时服务每天查一次（先 npmmirror 再 GitHub，不发送任何用户信息）：查不到就记成失败、十几分钟后再试，不占满一整天；`FLUENTFLOW_RELEASE_CHECK=0` 可以完全不查。页面和 `/release-check` 给出这一份的更新命令（Windows 一个文件夹安装给的是 `FluentFlow` 那一层，不是 `app`；文件夹按原样交给 shell，单引号，名字里有 `$(` 或引号也不会被当成命令），页面能一键复制；git 检出给的是 `git pull` 加安装脚本，安装命令也不接管正在运行的 git 检出（7.13、7.14）。
- Windows 验证到哪：后端测试全部通过（7.3）；发版前在 GitHub 的英文 Windows 机器上跑通一条命令安装和全套测试（7.5）；装到 D 盘、卸载干净、原地更新和失败换回、环境自愈都在那台机器上跑过（7.7、7.9）。中文系统的 Windows、国内真实网络、真实录像转录剪辑、NVIDIA 显卡、lark-cli 导出飞书都还没在 Windows 实机验过。
- 要用浏览器登录态下载链接，得给「终端」完全磁盘访问权限。安装时不提示，读取失败时才提示（1.3）。

### 7.2 启动和卸载脚本的已知问题（Windows 未实机验证）

2026-10-14

- Windows 启动器：运行 uvicorn 前把出错处理从「遇错即停」改为「继续」。Windows 自带的 PowerShell 5.1 会把原生命令写到错误输出的第一行当成致命错误，uvicorn 的启动日志正好写在那里，服务会一启动就退出。`.cmd` 在脚本出错退出时停住窗口，能看到原因。启动器的提示改成中文，文件加上 UTF-8 标记（没有它，PowerShell 5.1 会把中文读成乱码）；加了检查，以后有中文的 Windows 脚本缺这个标记会被测出来。
- Windows 卸载脚本：原来读 `/health` 里不存在的顶层字段，认不出正在运行的服务，会在服务运行中删环境；改为读 `edition` 和 `runtime.execution`。数任务时原来读错了任务列表的结构，也改了。
- 端口：启动器和卸载脚本在 macOS、Windows 上都按「环境变量 → 仓库 .env 里的同一行 → 8000」读，和后端一致。
- 前端没构建时的提示改成存在的命令 `npm run build:frontend`。
- yt-dlp 每日更新：同一时间只跑一个，第二个启动直接跳过；pip 的时限从 2 分钟放宽到 10 分钟，避免慢网络下把装到一半的 pip 杀掉；没设镜像时，默认源失败会再走一次清华镜像。
- 升级 yt-dlp 的那几秒里开始的链接下载：碰到「找不到 yt-dlp」时等升级做完（最多 20 秒）再试一次，不再直接报「yt-dlp 没装」。
- Windows 的安装（`setup-local.ps1`）、卸载、建桌面图标脚本的提示也改成中文，带 UTF-8 标记。一条命令安装的入口 `install.ps1` 保持英文：它是下载后直接执行的，开头的 UTF-8 标记在 Windows 自带的 PowerShell 里可能被当成代码，第一行就出错，而读它输出的主要是 agent。
- 以上都没在 Windows 实机跑过，跟待办里的实机安装一起验。

### 7.3 后端测试在 Windows 上全部跑通

2026-10-16 · 王愉超要求在新 Windows 电脑上跑 0.9.1 的测试

- 起因：Windows 上跑 `pytest`，1458 个测试中途就崩了（有个测试把 `os.name` 改成 `posix`，pathlib 跟着出错），排除它以后还有 38 个失败。
- 产品代码里确实有问题的几处：
  - 判断「是不是 ffmpeg」只比较文件名，Windows 上叫 `ffmpeg.exe`，所以导出进度和「电脑占用」档位在 Windows 上从没起过作用。改为一处统一判断（`device_profile.is_ffmpeg`）。
  - 调用子进程时只写了 `text=True`，没写编码，Windows 中文系统按 GBK 读写。传给 Claude 的中文提示、读回的笔记、带中文的 FFmpeg 输出都会出错。Claude 调用和 FFmpeg 命令入口改为明确用 UTF-8；启动脚本（`FluentFlowLocal.ps1`、`install.ps1`）打开 Python 的 UTF-8 模式，没写编码的其它地方也一并按 UTF-8 读写。
  - 用 npm 装的 `claude` 在 Windows 上是 `claude.cmd`，由它再启动 node。超时时只结束了 `.cmd` 这一层，node 还开着输出管道，调用要等它自己结束（实测超时 0.5 秒的登录检查过了 5 秒才返回）。改为结束整棵进程树（`process_tree.kill_tree`，内部用 `taskkill /T`）。链接下载停 yt-dlp 时引用了 Windows 上不存在的 `signal.SIGKILL`，也一并改了。
  - `with sqlite3.connect(...)` 只提交事务、不关闭连接，Windows 上连接没关的文件删不掉也改不了名。改为用完就关（`sqlite_connection`）。
  - 本地说话人模型的配置里，Windows 的路径以盘符开头，原来只认 `/` 和 `~` 开头的路径，缺文件也查不出来。
  - 交给 `claude` 的环境变量补上 Windows 需要的几项（`TEMP`、`PATHEXT`、`HOMEDRIVE`、`HOMEPATH`、`CLAUDE_CODE_GIT_BASH_PATH` 等），都不是凭据。
- 其余是测试本身只考虑了 Unix：用了 `sleep`、`/bin/echo` 和 sh 脚本，写死了 `/` 分隔符，读文件没写编码。改成在两个平台上都能跑。只有在 macOS 上才可能出现的那个用例（文件夹名里带反斜杠）在 Windows 上跳过。
- 结果：Windows 上 1457 个通过，11 个跳过（都是只在 macOS 或 CI 上才有意义的），0 个失败。安装和启动脚本仍没在 Windows 实机跑过，跟待办里的实机安装一起验。

### 7.4 Windows 启动器：日志用 UTF-8，路径和提示改对

2026-10-16 · 在王愉超的 Windows 电脑上实机使用时发现

- 日志：Windows 自带的 PowerShell 5.1 里，`Tee-Object` 用 UTF-16 写日志，又和 `Add-Content` 写的行混在同一个文件里，agent 读出来每个字中间隔着空格；运行期间文件还被锁住。uvicorn 写到错误输出的每一行都带着一段 `NativeCommandError` 说明，看着像报错。改为每行转回文字，显示到窗口并按 UTF-8 追加进日志，不占着文件；旧的 UTF-16 日志第一次启动时挪到 `local.log.1`。
- 路径：脚本里写的 `\\` 在 PowerShell 里就是两个反斜杠（反斜杠不是转义符），日志路径显示成 `FluentFlow\\Logs`，改成一个。找不到虚拟环境时的提示指向安装脚本，不再让人手动建 `venv`。
- 选择文件夹的对话框换成资源管理器样式的（有地址栏，能粘贴路径），老的树形对话框留作后备；按钮和标签跟着页面的语言，不再在中文系统上显示 Select Folder。
- 加了检查：有 PowerShell 的机器上跑测试时，用 PowerShell 自己的解析器检查每个 Windows 脚本，引号写错之类的问题会被测出来（CI 跑不了 Windows 脚本）。

### 7.5 发版前在 GitHub 的 Windows 机器上跑通一条命令安装

2026-11-09 · 王愉超要求发新版、Windows 能用是重点

- 做法：发版前在 GitHub Actions 的 windows-latest（英文系统，Windows PowerShell 5.1）上，对要发的代码跑 `install.ps1 -SkipModel`（`FLUENTFLOW_INSTALL_DIR` 指向检出目录，所以用的是这份代码，不下载 Release），再跑 `check_mcp_server.py --backend-e2e`、打开首页，同时在 Windows 上跑全套 `pytest`。检查脚本只放在临时分支上，跑完删掉，不进 main 的 CI。
- 查出并修好的四处，都是 0.9.1 就有的：
  - Python 版本：安装脚本只要求 3.10 以上，机器上默认是最新的 3.15 时就用它建环境，转录要用的 onnxruntime 没有 3.15 的预编译包，pip 报「找不到匹配的版本」，看不出是版本的问题。改为只用 3.10 到 3.14（Windows 按 3.12、3.13、3.11、3.14、3.10 的顺序问 `py.exe`，都没有就用 winget 装 3.12；macOS 在合格的里面挑最新的，没有就用 uv 装 3.12）；上一次用新 Python 装失败留下的虚拟环境会删掉重建。上限写在两个安装脚本里，onnxruntime、ctranslate2、faster-whisper 给下一个 Python 出包后再放宽。
  - 安装时的输出编码：被 agent 运行时输出走管道，Python 按系统代码页写，英文系统上是 cp1252，启动前检查的第一行中文就报错，安装在最后一步失败。`install.ps1` 和 `setup-local.ps1` 开头打开 Python 的 UTF-8 模式，并让 PowerShell 按 UTF-8 读程序输出；启动器也按 UTF-8 读服务的输出，窗口和日志里的中文不再乱码。
  - MCP 服务的编码：Claude Code、Codex 直接启动 MCP 服务，不带 UTF-8 模式，中文 Windows 上它按 GBK 收发：回给 agent 的中文是 GBK 字节，笔记里有表情符号时那次调用没有回答，agent 传来的中文（要替换的原文）被读错。MCP 服务启动时把收发都换成 UTF-8（`_use_utf8_stdio`），测试用 GBK 的流验证。
  - MCP 自检程序读服务的回复也改按 UTF-8，安装失败时提示用户手动运行的就是它。
- 结果：安装、桌面启动器拉起服务、网页打开、MCP 提交一条转录稿走完都通过；Windows 上全套测试通过。没验证到的：中文系统的 Windows（CI 只有英文系统）、用 winget 装 FFmpeg 和 Python（CI 上 FFmpeg 由 Chocolatey 预装，机器上已有 Python 3.12）、真实录像的转录和剪辑（没下载转录模型）、NVIDIA 显卡、用 lark-cli 导出飞书（Windows 上它若是 npm 的 `.cmd`，命令行里带 `&`、`|`、`<`、`>` 的正文可能被 cmd 拆开，未核实）。

### 7.6 Windows 上 FFmpeg 先从国内镜像下载，启动器重读系统路径

2026-11-21 · 王愉超的朋友在 Windows 上装时长时间卡在 FFmpeg（王愉超：没有国内镜像）；发 0.11.0 前的 Windows 检查同时查出启动器问题

- 问题一：缺 FFmpeg 时用 winget 装 Gyan.FFmpeg，安装包从 GitHub 下载，国内网络下可能很久没有进展，屏幕上也没有进度；pip、npm、转录模型都有国内镜像兜底，只有 FFmpeg 没有。
- 做法：先从 npmmirror（阿里云）下载 ffmpeg-static 的 Windows 版（6.1.1，gyan.dev 出的 essentials 版，和 winget 那个同一家，含剪辑用的 libx264、libmp3lame、aac），解压进数据目录的 `bin`，服务启动时本来就把这个目录放在 PATH 最前（`runtime_paths.put_bundled_tools_on_path`）；镜像连不上再用 winget。版本比 winget 的旧，CI 的 Linux 测试用的就是 6.1，够用。
- 问题二：`install.ps1` 装完直接打开桌面启动器，启动器沿用安装窗口在 winget 装 FFmpeg 之前的 PATH，启动前检查报「找不到 FFmpeg」并停在「按回车键关闭」，安装脚本干等四分多钟后报服务没启动。0.10.0 的发版检查能过，是因为当时 CI 机器预装了 FFmpeg。做法：启动器在启动前检查前把注册表里的 PATH 补到当前 PATH 后面（当前的在前，用户自己指定的 FFmpeg 仍优先）。
- 没验证到的：国内真实网络下的下载速度（CI 在国外）；中文系统的 Windows。


### 7.7 Windows 整个产品装进一个选定盘的文件夹；每样下载都有国内来源；卸载交给 agent 也能做

2026-11-21 · 王愉超的朋友在 Windows 上装时卡在 FFmpeg，而且全部装进 C 盘；他定：整个产品（代码、Python 环境、数据、FFmpeg、转录模型）放进一个选定盘上的一个文件夹，所有下载都要有国内来源，卸载要方便并给 agent 写说明；一键安装命令和代码包的国内地址他定「走 npm」

- 一个文件夹：`install.ps1` 有别的盘时推荐 C 盘以外剩余空间最大的盘（要约 10 GB），人在控制台运行时列出各盘问一句（回车用推荐），agent 运行时不问，照 `FLUENTFLOW_INSTALL_DIR` 或推荐走；C 盘用 `%USERPROFILE%\FluentFlow`，别的盘用 `X:\FluentFlow`。里面 `app`（代码和 Python 环境）、`data`（任务、下载的 FFmpeg 和 Node.js）、`models`（转录模型，`HF_HOME`）、`downloads`（链接下载）、`cache`（pip、uv、npm 缓存），位置写进 `app\.env`。之前的布局（代码直接在 `%USERPROFILE%\fluentflow-local`）照旧沿用；已有的一个文件夹安装会被找到，不重新选盘。Python 本身没有时装在 C 盘（和普通装 Python 一样）。`AGENT_INSTALL.md` 让 agent 装之前先问用户装哪个盘。
- 同一套规则读 `.env`：数据目录、模型位置只写在 `.env` 时，安装脚本、启动前检查、卸载脚本原来只看环境变量，会用默认目录。改成 Python 的入口都先调 `runtime_paths.load_project_env`（不依赖第三方库，和 python-dotenv 的读法有测试对齐），PowerShell 和 shell 脚本用 `fluentflow-env.ps1`、`fluentflow-env.sh` 里同一条规则（先环境变量，再 `.env` 最后一行）。实测：`HF_HOME` 只写在 `.env` 里，模型脚本列出和下载的都在那个目录（测试 `test_hf_home_in_env_moves_the_transcription_models`）。Windows 实测还查出一个 bug：服务在读 `.env` 之前就定死了设置文件的位置，填的 Key 会存进 C 盘默认目录；改成每次现算。
- 国内来源：每样下载按「先探原站 5 秒拿 1 MB，连不上或不到这个速度就先走镜像，失败再换另一个」处理（`backend/core/download_source.py` 和两个 shell 文件里同一条规则）。Python 安装包（python.org / npmmirror，3.12.10，只给当前用户装、不弹窗）、Node.js（nodejs.org / npmmirror）按固定 SHA-256 核对；说话人模型分段的从 ModelScope、嵌入的从 hf-mirror，按 SHA-256 核对（2026-11-21 核过和 GitHub 上的逐字节相同）；pip 用清华源、npm 用 npmmirror。代码包：GitHub 慢就从 npmmirror 下 npm 包 `fluentflow-local`（按 npm 记的 sha512 核对）；国内的一键安装命令是 `registry.npmmirror.com/fluentflow-local/latest/files/install.ps1`（Mac 是 `install.sh`）。发版时 `.github/workflows/release.yml` 用 `scripts/stage_npm_package.py` 打包发到 npm：第一次用仓库密钥 `NPM_TOKEN`，之后改用 npm 的可信发布（npm 计划 2027 年 1 月停用能跳过两步验证直接发布的令牌），两样都没有时跳过不报红；他要做的步骤在维护手册「发到 npm」。
- 卸载：注销 Claude Code、Codex 里的 `fluentflow-local`（只在它指向这份安装时），删给 agent 的 skill、下载的 FFmpeg 和 Node.js；用发布包装的连代码文件夹一起删，git 检出只删环境不删代码；Windows 一个文件夹装的 `-All` 删完不留文件夹。先结束从这个文件夹运行的程序；调用卸载的窗口正站在文件夹里时，把里面清空并说明还剩哪个空文件夹。`AGENT_INSTALL.md` 有卸载一节（先看再删，任务数据单独问用户）。
- Windows 实测查出、0.11.0 就有的问题：npm 装的 Claude Code、Codex 在 Windows 上是 PowerShell 外壳，它们往错误输出写一行（注册前的「No MCP server named …」），在「遇错即停」下安装脚本整个停在最后一步，卸载脚本把已注册的工具当成没有。改成 `Invoke-FluentFlowTool`：调真正的程序（不是外壳，外壳会吞掉 `--`），出错不停，返回退出码和输出。

### 7.11 第 5 批审查后：更新和卸载不再删掉读不准位置的数据、不是 FluentFlow 的文件

2026-11-26 · 两家独立审查第 5 批查出，主对话核对后定为必须修的两条和顺手修的两条

- 读不准位置就删：数据目录写成相对路径（服务在代码目录里运行，数据就在代码目录里）、写成 `${HOME}/…` 引用或 `~`，更新前的检查和卸载都只认完整路径，判成「不在代码目录里」：更新成功后删旧代码时连数据一起删，「保留数据」的卸载把整个代码目录删掉。Windows 上还因为读 `.env` 不按 UTF-8，中文路径对不上。AGENT_INSTALL 让 agent 给 C 盘写 `%USERPROFILE%\FluentFlow`，PowerShell 不展开它，正好装出相对路径。改法：更新检查和两边卸载都照服务的读法定位置（展开引用、`~`、相对路径从代码目录算、按 UTF-8 读，Mac 再解开链接比一次），展开后还剩 `$` 这类读不准的一律当作在代码目录里，更新停下、卸载不整个删代码目录，并说清是哪一项。读法在 `launchers/windows/fluentflow-env.ps1`（`Resolve-FluentFlowPlace`、`Test-FluentFlowInside`）和 `launchers/macos/fluentflow-env.sh`（`ff_place`、`ff_inside`）；`install.ps1`、`install.sh` 在换代码前用不上两份脚本，抄一份一字不差的，测试守着。
- 装到哪：`FLUENTFLOW_INSTALL_DIR` 先展开 `%VAR%` 和 `$env:VAR`（agent 常写在单引号里），转成完整路径、去掉结尾的 `\`；整个盘的根目录不接受（卸载会清空安装文件夹）。原来结尾带 `\` 时 `.env` 里写成 `'D:\FF\'`，服务的读法把 `\'` 当成转义的引号，把下一行也读进值里。写 `.env` 的函数也不再写出结尾的 `\`。AGENT_INSTALL 改成 `"$env:USERPROFILE\FluentFlow"`。
- 删数据删到别人的文件：`--all` / `-All` 原来整个删数据目录。数据目录被指到用户自己也在用的文件夹时，他的文件会一起没。现在只有里面全是 FluentFlow 认得的东西才整个删；有认不出的，只删认得的，认不出的留下、文件夹留着，删前（包括只看不删）和删后都列出来。认得的清单只有一份：`launchers/data-folder-contents.txt`，测试扫代码里往数据目录写东西的地方（`runtime_path`、`app_data_root() / …`、两边安装脚本里的数据目录子文件夹），有没登记的就失败。`bin`、`models` 这类常见名字只按名字认不够，第二轮审查后改成还要看里面装的（见下）。
- 更新标记认错：更新标记原来写进每一份代码（包括正在用的那份），用户自己复制或改名出的 `app.old`、`fluentflow-local.old` 也带着它，会被更新或卸载删掉。现在标记写明更新把这份放在了哪，只有写的就是它现在的位置才算更新留下的；正在用的那份不带标记。
- Mac 卸载不停后台下载转录模型的进程，装完马上 `--all` 会剩几 GB。照 Windows 那样先停掉从代码目录运行的程序（不算卸载脚本自己）。
- 验证：每条先写了在改之前失败的测试（`tests/test_install_places.py`：Mac 上真跑 `install.sh` 和卸载脚本的沙箱，另设 HOME、端口 9、PATH 里没有 claude 和 codex；两边读法的对照用例；Windows 那几条只在 Windows 上跑）。写测试时还查出新写法里两处毛病并改掉：标记里不是路径时 `ff_physical` 死循环；`FLUENTFLOW_INSTALL_DIR` 本身被当成「设在代码目录里的位置」。Windows 实测（GitHub windows-latest，临时分支三轮，最后一轮 https://github.com/Userneima/fluentflow-local/actions/runs/45746180516 全过）：`FLUENTFLOW_INSTALL_DIR='D:\FFA\'` 装好后服务读 `.env` 得到 `D:\FFA`、`D:\FFA\data`、`D:\FFA\models`，代码文件夹里没有数据；写成单引号里的 `$env:USERPROFILE\FFB` 装进用户文件夹；`.env` 改成 `FLUENTFLOW_DATA_DIR=data` 或 `$HOME\data` 时更新停下、什么都没动；`-Models -Yes` 卸载留下代码文件夹和里面的数据、删掉虚拟环境；用户自己复制的 `app.old` 拦住更新且原样留着，删掉后更新 56 秒到 0.12.0、正在用的那份不带标记；数据文件夹里放了别的文件和文件夹后 `-All` 只删 FluentFlow 的，别的留着、先看时列出来，用户的 `app.old` 不在删除清单里。`tests/test_install_places.py` 在 Windows 上 28 条过（PowerShell 那几条只在那里跑）。
- 第二轮审查（Claude 子 agent 和 OpenCode 各审一遍，主对话核对）又查出八处，都改了：
  - 常见名字按名字删：数据目录指到共用文件夹时，用户自己的 `models`、`bin`、`logs` 会被当成 FluentFlow 的删掉；卸载程序时删 `bin`、`tools`、`cache` 也是这样。现在清单对常见名字写明里面该有什么（`bin` 只有 ffmpeg、ffprobe、uv，`models` 只有 speaker、pyannote，`sources`、`artifacts` 里是任务编号命名的文件夹……），名字对、里面每一样也对得上才算 FluentFlow 的；对不上的留下并列出来。任务编号是调用方自己给的（agent 可以指定）时，那个任务的文件夹对不上编号的样子，会被留下、列出来，只会少删。
  - Mac 读法展开 `${NAME}` 取的是文件里最后那行同名的，服务取这一行之前的；改成按行的顺序。`${NAME:-默认值}` 也照服务的规则展开，没有当成读不准：安装脚本按同一个函数定数据目录，留着原样会在磁盘上建出名字叫 `${…}` 的文件夹。
  - 引号在本行没闭合（结尾的 `\'`、`\"`）时服务会把下一行读进这个值，下一行也就不再是一项设置；现在这一行和它之后的都当读不准。两边的读法都照服务解引号里的转义（Windows 原来先换 `\n` 再换 `\\`，`"D:\\notes"` 读成带换行）。

  - bash 5.2 起 `${x//pat/rep}` 里的 `&` 代表匹配到的那段，值里有 `&` 时（`R&D`）展开引用的循环永远停不下；改成一段段拼起来。
  - Mac 停程序原来命令行任何位置提到代码目录就停，现在只停以这个目录虚拟环境的 python 开头的，或一个 python 直接跑这个目录里的脚本的（Homebrew 的 Python 会换成框架里的 Python 再跑）。
  - 更新检查和卸载原来窗口里设了某项就不看 `.env` 那行；之后由启动器起的服务不一定带着窗口的环境变量，现在两处都看，任一处在代码目录里或读不准都停。

### 7.12 文件夹挪盘、装着装着断了、装在自选文件夹：位置和中断都要认得出来

### 7.13 注册、卸载、更新检查：按实际的来，文档照实写

2026-11-26 · 同一批审查建议

- MCP 注册：原来「已存在就不动」，安装删了或挪走以后留着指向失效文件的条目；卸载用 `claude mcp get` 查、删却固定 `--scope user`，项目级那条删不掉；Codex 的配置写死 `~/.codex`。现在：指向这一份的留着；指向另一份还在的安装也留着并说明；指向的文件不在了就按查到的那个作用域注销再注册，Codex 认 `CODEX_HOME`（`ff_codex_home`、`Get-FluentFlowCodexHome`，装 skill 的目录也一起）。两边卸载同样按查到的 `-s <作用域>` 注销。

- 更新检查（`backend/core/release_check.py`）：查询时间原来在发请求前就记下，启动时没联网要等 24 小时才再查；现在查不到就记成失败，15 分钟后可以再查，查到了才算这一天的。加开关 `FLUENTFLOW_RELEASE_CHECK=0`（不联网查、页面也不提示）。git 检出上不再提示「再运行安装命令」，页面和 `/release-check` 的 `update_command` 给的是 `git pull` 加安装脚本。
- 镜像和校验的说法照实写（README、AGENT_INSTALL 和本节）：按固定 SHA-256 核对的是 Node.js、Windows 的 Python 安装包和 FFmpeg、说话人模型、npm 上的代码包；pip 装的库按锁定文件的版本、转录模型按模型名下载，不逐个核对哈希；macOS 的 FFmpeg（`ffmpeg.martin-riedl.de`）和「没有合格 Python 时用来装 Python 的 uv 程序本身」没有国内镜像。yt-dlp 的每天升级仍是先走默认源（或用户设的 `PIP_INDEX_URL`），失败才走清华源，维护手册照这样写。没有去补固定版本和校验值：这几处要么没有官方校验文件，要么补了就得跟着上游手工改，收益小于维护成本；写清楚比写得好看重要。

### 7.14 第一轮审查的七条：挪盘判断、带空格的路径、按文件夹更新、更新中途的状态

2026-11-27 · 第一轮独立审查对 7.12、7.13 提的七条，主对话核对后全部要修

- 「文件夹不见了」不等于「文件夹挪走了」：`Repair-FluentFlowHome` 原来只看到旧位置不在就改 `.env`。U 盘或网络共享没接上时，旧位置也「不在」，改完等它接回来数据就再也对不上了。现在只在旧位置的盘符/卷根还在、只有文件夹不在时才认作挪动；卷根也不在时原样留着并说一句（「`FLUENTFLOW_HOME` 指的是 D:\…，D:\ 现在不可用，`.env` 没动」）。`.env` 里没有 `FLUENTFLOW_HOME`、或那一项照服务的读法看不准（还剩 `$`、引号没闭合、不是 UTF-8）时同样不动，也说一句。
- 带空格的路径：注册条目里认「它启动的是哪个脚本」原来取 `Args:` 那行最后一个词，`C:\Users\John Smith\…`、`/Users/John Smith/…` 会被截断，`Test-Path` 落空，然后删掉另一份还在用的注册。现在取最后一个「空格后面开始、到行尾」的绝对路径（Windows 上从各个词往后拼，只认恰好一个盘符路径结尾是 `scripts\fluentflow_mcp_server.py` 的那种）；看不出是服务脚本就不删，并说明认不出。Codex 那一节同理：读得出它启动的脚本、那个文件又不在才算失效（`codex_entry_is_stale`），`args` 写法认不出时不动。
- 卸载时换作用域删：Mac 卸载原来在查到的作用域删失败后又用 `--scope user` 删一次，那可能正是另一份安装的注册（两份都能注册在 user）。现在只在查到的那一个作用域里删（查不到才按 user），失败就提示手动命令。
- 更新命令给出的是代码目录：Windows 一个文件夹安装的代码在 `D:\FluentFlow\app`，`/release-check` 的 `update_command` 原来把 `app` 当成安装位置，安装脚本收到它会当成旧布局（跳过安装标记、权限这些检查）。现在 `install_folder()` 看到 `app` 旁边有 `.fluentflow-home` 就给出上一层；页面把这个命令显示出来并可复制（侧边栏更新提示里一块等宽字 +「复制更新命令」），不再只说「再运行一次安装命令」。
- 运行时是 git 检出时不接管：更新命令运行前会问正在运行的服务装在哪；如果那是一份开发者的 git 检出，原来会把这条安装命令套到检出上（跑它的安装脚本、往里面构建界面）。现在跳过并说明（git pull 更新它），按默认位置装这一份。
- 更新标记写在挪文件夹之后：断电正好卡在两次 `mv` 之间时，旧版本已经在 `.old` 里却没有标记，下次运行当成没装过，另装一份并用**默认的** `.env`（访问令牌、数据目录设置全丢）。现在标记在挪之前就写进旧的这份、写的是它将要去的位置（`ff_mark_update_copy_as`、`Set-FluentFlowUpdateCopyAs`），挪不动时删掉。
- 换 `.env` 会先清空再写：Windows 的 `Set-FluentFlowEnvLine` 用 `WriteAllLines`，那一刻启动的服务或启动器可能读到空文件、按默认数据目录跑。现在写到同目录的 `.env.writing` 再整体替换（`File.Replace`，读的人占着就重试五次、仍不行就保留原文件并说一句）。

#### 7.14 第二轮审查：真实输出形状、抢标记的竞态、更新命令的引号、被顶掉的临时目录
