# 一、提交素材

决策记录的一节，写法见 [决策记录](../02-决策记录.md)。

**现状**（2026-11-19 按决策条目核对）

- 三种来源：
  - 本机文件：用系统选择框选文件或整个文件夹，macOS 用 osascript，Windows 用 PowerShell 调系统对话框（1.10）；原地读取、不复制，页签叫「本机文件」（1.7）。一次最多 30 个，多选的确认框写明这次处理前 30 个、剩下几个要再选一次，后台回复列出没处理的路径（1.6）。
  - 网页上传（拖入的文件找不到原位置、或系统既不是 macOS 也不是 Windows 时）：复制进 FluentFlow 的数据目录，一次最多 30 个、大小不限，和本机文件同一个标准；`FLUENTFLOW_MAX_UPLOAD_MB`、`FLUENTFLOW_MAX_QUEUE_FILES` 可设上限（1.8）。
  - 视频链接：抖音、B 站、YouTube 和视频直链，一次一条，最多同时下载两条。下载的视频放进 `~/Movies/FluentFlow/<标题>/`，Windows 放系统记录的「视频」文件夹（6.12、6.14）。
- 常见视频和音频格式都收；其中 .wmv、.flv、.wma 能转录，但不剪气口。
- 链接下载：
  - 不限大小，下载前按平台给的大小看磁盘，下完剩不到 2GB 就先拒绝；服务器不报大小时边下边看，剩不到 512MB 停下；超时上限 6 小时。想设上限用 `VIDEO_SOURCE_MAX_BYTES`（1.5）。
  - B 站、YouTube 用 yt-dlp，默认下载视频（最高 720p）再自己转录；有字幕时只拿字幕要设 `FLUENTFLOW_CAPTIONS_FIRST=1`（1.9）。
  - 抖音交给第三方解析服务 miuistore，只发链接。图文帖提交时就拒绝；付费视频下载后报「像是抖音的付费视频」（6.61）。下载抖音视频文件连不上时提示可能是全局 VPN（1.13）。
  - B 站、抖音经代理被回 412 时改为直连再试一次，任务记录写明（1.11）。
  - 登录态从浏览器读，每个站点挑存着它登录信息最多的浏览器配置。读不到浏览器文件夹时，按系统提示去开权限：macOS 是给「终端」完全磁盘访问权限（1.3），Windows 不再指向 macOS 设置（6.58）。
- 选项：「只要转录」不写笔记（1.1）；传入的标题只在提交单个文件时生效，本机文件和链接都用作任务名（1.2）。agent 提交本机文件或链接时传 `cut=false` 就不剪也不等剪辑判断，笔记读原片（1.14）；`cut_judge` 选谁判断剪辑见 2.15。
- 录像多长都收，不设时长上限（1.4）。想限制的在 `.env` 里设 `FLUENTFLOW_MAX_MEDIA_DURATION_SECONDS`：本机文件和上传在剪完气口、开始转录时按剪后长度检查，链接在下载前按平台给的时长检查。
- 排队：一次处理一个任务，按提交顺序。转录存好、排队等剪辑的任务状态保持「完成」，新提交的才是「排队中」（1.12）。服务重启时，没做完的任务按原顺序重新排队；同一个任务连续被打断两次后留给用户处理。
- agent 通过 MCP 提交本机文件、链接或现成的转录文字，走同一个队列。

### 1.1 「只要转录」就不写笔记

- 决定：记下调用方的选择并遵守。

### 1.2 agent 提交本机文件时传的标题用作任务名

2026-10-14 · 提交 65d0c10

- 此前被丢掉，任务仍用文件名；提交链接时本来就用传入的标题。

### 1.3 检测浏览器登录态失败时，直接指向 macOS 权限

2026-10-14 · 提交 6c39ed5

- 原因：FluentFlow 由「终端」运行启动脚本拉起，「终端」没有完全磁盘访问权限，macOS 拒绝读取浏览器的数据文件夹。yt-dlp 把「被拒绝」报成「找不到数据库」，旧提示又让用户去确认浏览器装没装，方向错了。
- 决定：先自己检查浏览器文件夹能不能读，被拒绝时直接说要去「系统设置 → 隐私与安全性 → 完全磁盘访问权限」打开「终端」，再重开 FluentFlow。
- 依据：王愉超打开权限并重启后，读到 Edge 两千八百多条登录信息，B 站为登录状态。

### 1.4 去掉默认的时长上限

2026-10-14 · 王愉超定

- 问题：默认 4 小时上限，本机文件要等剪完气口、开始转录时才检查。超长的录像先白剪一轮再被拒。
- 原因：这个上限是托管版带过来的。托管版的转录和笔记花的是服务器的钱，按时长限制是为了控制成本；本地版处理的是用户自己的录像、用的是他自己的机器，代码和文档里没有它存在的理由。
- 考虑过：挪到提交时按原片时长检查。这样 4 到 5 小时、剪完能落进 4 小时的录像会从「能处理」变成「提交时被拒」，而且是在修一个本地版本来不需要的限制。
- 决定：默认不限，想限制的仍可在 `.env` 里设。
- 没验证过：超过 4 小时的录像还没跑过完整流程。转录分块进行、长录像的笔记按每段 6 万字分开写，设计上不受长度限制；真出问题，结果也是任务失败，和原来被上限拒掉一样。第一条真实的长录像就当作验证，出问题再查。

### 1.5 链接下载不限大小，只看磁盘空间够不够

2026-10-14 · 托管版遗留问题清理

- 问题：链接下载的大小上限沿用网页上传的 2GB。720p 大约每小时 1GB，三四个小时的课程链接下载前就被拒，重试也没用。这个上限是托管版保护共享服务器用的。
- 决定：默认不限大小。真正限制本机下载的是磁盘：下载前按平台给的大小估算，下完磁盘剩不到 2GB（剪辑和转录还要写文件）就先拒绝，提示清理空间。想设上限的用 `VIDEO_SOURCE_MAX_BYTES`。
- 直链和抖音下载由服务器在开始下载时报大小，同样按它检查磁盘；服务器不报大小时，边下边看，磁盘剩不到 512MB 就停下。
- 720p 的画质上限保留：截图和转录够用，下载更快更小。
- 下载超时：按视频时长和大小估算的超时原来最多一小时，四个多小时的链接一定超时。上限改为 6 小时，只用来拦住卡死的下载。

### 1.6 一次选超过 30 个文件时说清楚，不悄悄丢

2026-10-14 · 托管版遗留问题清理

- 问题：系统选择框一次选超过 30 个文件，后台只取前 30 个，其余直接丢掉；确认框还写着「选了 N 个」。
- 决定：30 个的上限保留（每个文件都要占几分钟处理器、写一次笔记，和选文件夹一样）。确认框写明这次处理前 30 个、剩下几个之后再选一次；后台的回复里列出没处理的路径，agent 或旧页面多传了也知道是哪些。

### 1.7 本机文件不再叫「上传」

2026-10-14 · 托管版遗留问题清理

- 问题：首页页签叫「本地上传」，各种出错提示让用户「下载到本机后上传」「上传本地视频」，README 也这么写。本地版从选择框选的文件是原地读取的，不复制、不离开电脑，「上传」是托管版的说法。
- 决定：页签叫「本机文件」，提示统一说「下载到本机后用「本机文件」处理」「改用本机上的视频文件」。真的会复制一份的地方（拖入的文件找不到原位置时的网页上传、上传中的状态）照旧叫上传。

### 1.8 网页上传和选本机文件同一个标准

2026-10-14 · 托管版遗留问题清理

- 问题：网页上传一次限 5 个文件、单个 2GB，从选择框选文件一次 30 个、大小不限。网页上传在本地版只是拖入的文件找不到原位置时的退路，5 个和 2GB 都是托管版保护服务器用的。
- 决定：网页上传一次 30 个、默认不限大小，和选本机文件一致。想限制的仍可设 `FLUENTFLOW_MAX_UPLOAD_MB`、`FLUENTFLOW_MAX_QUEUE_FILES`。

### 1.9 YouTube、B 站链接默认下载视频，不再只拿字幕

2026-10-15 · 王愉超定

- 问题：链接有字幕时只拿字幕当转录稿，不下载视频，任务里没有视频：笔记没有画面可看，没法剪，也留不下原片。
- 决定：默认下载视频（最高 720p）再自己转录，和本机录像一样。拿字幕代替转录要大改处理流程，省下的只是一小时视频十来分钟的转录，而自动字幕质量一般，投产比低；想只要文字快一点的，设 `FLUENTFLOW_CAPTIONS_FIRST=1`。

### 1.10 Windows 也用系统选择框选文件

2026-10-16 · 在王愉超的 Windows 电脑上实机使用时发现

- 问题：系统选择框只做了 macOS（osascript）。Windows 上点「选择文件」退回网页上传：录像复制一份进数据目录，剪后视频和笔记也不会放在原片旁边，本地版最主要的那条路在 Windows 上走不通。
- 决定：Windows 用自带的 PowerShell 调出系统的「打开文件」和「选择文件夹」对话框（Windows Forms），返回真实路径，后面和 macOS 走同一条路。对话框挂在一个看不见的置顶窗口下，不会躲到浏览器后面；提示文字和起始文件夹经环境变量传进脚本，不拼进脚本，文件名里有引号、反斜杠也不会改变脚本做什么。
- 依据：实机打开对话框选中 `周会 2026-10-16\周会录像.mp4`（带中文和空格），返回的路径正确；任务原地处理，原片旁边出现同名文件夹，里面有剪后视频、转录稿和字幕。

### 1.11 国内网站经代理被拒时，改为直连再试一次

2026-10-16 · 在王愉超的 Windows 电脑上用 B 站链接实测时发现

- 现象：B 站链接全部失败，页面说「B 站没有返回可下载的视频，请在 B 站里打开确认」。照着做什么也解决不了。
- 原因：这台电脑的加速器设成了系统代理（`127.0.0.1:19828`），B 站对从代理出去的请求一律回 HTTP 412；同一个链接不走代理马上就能列出格式。很多国内用户的电脑都这样设。
- 决定：B 站、抖音的 yt-dlp 请求在走代理时被回 412，就不走代理（`--proxy ""`）再试一次；同一个链接后面的步骤也直连，任务记录里写明「经代理访问被网站拒绝，已改为直连」。没有代理时、或是 YouTube 这类本来就要经代理访问的网站，不这样做。

### 1.12 转录完的任务排队等剪辑时，状态仍是「完成」

2026-10-27 · 一次批量处理 Skardi 会议录像时发现，读代码确认

- 现象：同时提交的几条录像里，排在后面的两条剪完后被记成失败（「Worker exited without a terminal state」），agent 取写笔记的材料被拒（「只有已完成的任务能重写笔记」）。排在最前面的那条正常。
- 原因：agent 判完剪辑后，任务要重新排队等着导出剪后视频。前面有别的任务时，排队记录把任务状态从「完成」改写成「排队中」，导出完没人改回来，任务结束时被当成没有结果而记为失败。
- 决定：转录稿存好的任务排队等剪辑时，排队记录照常写「在等谁」，状态保持「完成」；新提交的任务排队时仍是「排队中」。测试 `tests/test_cut_turn_keeps_completed.py`。

### 1.13 抖音视频文件下载连不上时，提示可能是 VPN

2026-11-03 · 2026-10-30 实测、10-31 查明（原待办「抖音链接在「取素材」失败时，报错没说可能是 VPN 的原因」）

- 起因：10-30 一条抖音链接三次都卡在「取素材」约 4 分钟后失败，报「连接在传输中途被断开了」。10-31 逐步跑三遍：解析三步（miuistore 的 `dy-check`、`dy-d` 结果页、`apikr.convry.com` 内层结果）每次几秒内成功、拿到 `*.douyinvod.com` 下载地址，下载视频文件这一步每次 30 秒左右 TLS 握手超时；本机开着全局模式的 VPN，出口在美国。切成智能代理后三遍都在 3 到 24 秒内下完 20MB。代码没问题，是全局 VPN 把抖音视频的下载绕到了境外。
- 决定：下载抖音视频文件本身（`douyinvod.com`、`amemv.com`、`snssdk.com`）时，连不上（TLS 出错、连接断开、超时、地址解析不了）报「抖音视频下载连不上」，提示把 VPN 切成智能或规则模式、或把抖音设成直连再重新提交（`video_source.download_file`，判断词在 `local_error_diagnostics` 和页面的 `format.js` 两层都加）。服务器回了错误（403 这类）不算，解析那几步和别的网站断开仍按原来的「网络连接中断」报。

### 1.14 agent 只要转写稿时提交 `cut=false`，不剪也不等判断

2026-11-17 · 知识短片对话报告，王愉超让 fluentflow-local 对话修（原待办「只想要转写稿时没法『什么都不剪』」）

- 起因：知识短片对话给一条 B 站视频只要转写稿，`save_agent_cut` 传空的保留和删除列表，FluentFlow 仍按默认剪掉短停顿和一段画面在变的空白，剪辑处理说明也留成没写完。
- 决定：`submit_local_media` 和 `submit_video_link` 加选项 `cut`（默认 true）。`cut=false` 时转录完不等 agent 判断、也不剪，剪辑这一步记为跳过，没有待写的处理说明；笔记（要写的话，FluentFlow 写或 agent 写都一样）读原片、带画面，压缩版、飞书、输出文件夹照没剪的任务走（`visual_note_job.cut_media`）。这个选项和 `cut_judge` 记在一起（链接记在任务元数据，本机文件记在原地读取的来源里），重新提交、接着做都保留；判断在 `agent_cut.cut_declined`。网页不加开关。
- `save_agent_cut` 传空列表的意思不改，仍是「按默认剪」：讲课录像最常见的判断就是没有要特意保留或额外删除的地方，空列表若改成「全部保留」，这类任务就一刀不剪了。测试 `tests/test_transcript_only_no_cut.py`。
