### 4. 这次得出的经验

- **用真实任务库的副本起完整服务前，先关掉副本里没到终点的步骤**：第二批起启动时会把这些任务接着做，8000 上正在跑的任务会在副本里再跑一遍、花钱、写原片旁边的产出文件夹。这次撞上一次，启动完成前停掉了。落点：写进 `docs/04-维护手册.md`「模型用量和价格表」一节末尾。
- **DeepSeek 国内平台按人民币扣费，人民币价是中文定价页上的另一套，不是英文页美元价的换算**（flash 高峰输入 2 元/百万，英文页 0.3 美元/百万）。落点：决策 6.44、价格表的 `peak_note`、维护手册。
- **测试替身漏了一个出口时，用「服务商看到几次 = 记了几行」这种对账式断言能抓到**：这次整条任务测试里一次调用走了没替换的订阅命令行，跑到真实的 `/usr/bin/true`，对账对不上才发现。跨项目：测「每次 X 都被记录」时，替身自己数一遍，跟记录对账，别只断言「有记录」。
- **会话记录是订阅调用 token 的独立来源**：Claude Code 每次 `-p` 运行在 `~/.claude/projects/<目录名>/` 留一份 jsonl，同一条消息会出现在多行里，按消息 id 去重后相加，等于 result 事件的 usage。跨项目。
- **`contextvars` 在 `run_in_executor` 和自建线程池里不跟过去，`asyncio.to_thread` 会跟**；同一个 `Context` 不能在两个线程里同时 `run`，每次运行要 `copy()` 一份。跨项目。
- 实测数字：4 分钟片段走订阅 5 次调用、输入 11.3 万 token（47% 来自缓存）、输出 6226，命令行折算 0.61 美元，写正文那次最大（3.3 万输入、0.22 美元）。落点：决策 6.44、测试记录。
