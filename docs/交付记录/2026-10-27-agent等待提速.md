## 交付单

### 1. 改了什么

提交：`7412e37`。

**需求 1，等待几乎不花额度**

- 服务端 `wait_task` 一次最多等 600 秒（原来 60 秒）；MCP 工具默认等 240 秒，HTTP 超时跟着放宽。
- 立刻返回的情况多了一种：剪辑定下、开始导出、笔记归 agent 写时，返回一次 `agent_note`（ready、next），每条任务只说一次。
- `SKILL.md`、`AGENT_INSTALL.md`、MCP 工具说明写明：提交后只告诉用户一次，之后连续等待、中间不说话、不查进度；写笔记交给不继承这段对话的子助手。

**需求 2，导出期间就能开始写笔记**

- 剪辑决定在导出前存到任务上时，连留下的几段、属于哪一次导出一起存（`survey_cut._remember_decision`）；`survey_cut.ranges_while_rendering` 只在这一次导出进行中时给出这几段。
- 导出期间取笔记材料按「原片当成剪后」给：转录稿换算到剪后时间轴，截图从原片的对应时刻截（`agent_note._eligible`、`_frames`），和 FluentFlow 自己写笔记那条路相同。
- 取材料接口在「队列忙」是这条任务自己在导出时不再拒绝。
- 导出期间存的笔记、导出随后失败：在 agent 任务走的那条流程里换回原片时间轴（`task_flow._agent_note_back_onto_original_if_uncut`）；导出失败或停下之后才交回的剪后时间笔记，存时拒绝并说明怎么办。
- 剪辑还没定时取材料，明确拒绝（原来会按原片时间轴给「只有转录稿」的材料）。

### 2. 怎么验证的

- 整套：`pytest -n auto` 2114 过、3 跳过；`ruff` 通过；`git diff --check` 通过。没改前端。
- 假模型测试副本（`prepare_test_copy.py --fake --port 8013`）上用脚本扮演 agent 跑一条 66 秒片段：共 8 次工具调用，其中等待 3 次；交回剪辑决定后第二次等待 4 秒就以「可以开始写笔记」返回，取材料、存笔记时导出还在进行，导出完转录稿在剪后时间轴、笔记是 agent 存的那篇。

## 验收

主对话自己做完的活，按 `subsession-acceptance`「主对话自己做完一块活」自查，派了一个没参与修改的子代理对照需求独立审。

审出的问题和处理（都在 `7412e37` 里）：

1. 导出失败后才交回的、按剪后时间写的笔记会落到错的时间轴上，流程里的「换回原片」只在剪辑结束那一刻跑一次。修：取材料时记下这份材料是不是按剪后给的，存时发现剪后视频没出来就拒绝并说明。
2. 「可以开始写笔记」原来以「取过材料」为准不再返回，子助手还没开始或取材料失败时，每次等待都会立刻返回，又变成空转。修：改成返回过一次就不再返回。
3. 导出失败后留下的剪辑决定，会被之后不重新判断的导出（改判、手动重剪）当成当前的决定。修：决定记下属于哪一次导出，对不上不给。
4. 新接线没有测试守着（删掉那一行测试照过）。修：改成从流程入口测；以上三条也各补了测试，逐条把修复改回去都会失败。
5. 重启后重新导出可能换出不同的留下区段：核过不会，留下区段始终由剪掉的几段和片长按同一个函数算出，重放时一样。不改。
