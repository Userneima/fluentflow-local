### 4. 这次得出的经验

- **测试启动整个应用时，启动阶段的自动续接会把别的测试留下的任务排进来**：`create_local_app()` 的启动会续接库里步骤没结束的任务，测试共用一个库时会互相串。启动整个应用的测试要把续接关掉（`task_actions.stepped_tasks_cut_off` 打成空）。只关这个项目：写进了测试本身（`tests/test_task_entry_routes_http.py`、`tests/test_link_download_files.py`）和本交付记录。
- **React 钩子依赖调用方每次渲染新建的函数，会让 effect 每次渲染都跑，测试卡死不报错**：编辑页的测试替身 `useApi()` 每次渲染返回新的 `getJob`，`useTaskResume` 的 effect 依赖它，结果每次渲染都读一次、改一次状态，整套前端测试跑了 30 分钟没结束。改成把调用方的函数放进 ref。跨项目（和全局规则里「替身对象只建一次」是同一类事，这条是被测代码这一侧的写法）。
- **给已有页面加一个读请求，会吃掉测试里按顺序排好的替身返回值**：编辑页测试用 `mockResolvedValueOnce` 排好 `getJob` 的几次返回，多读一次就错位。新功能用单独的接口函数（`getJobActivity`），老测试的替身里没有它就不读。跨项目。
- **停掉 uvicorn 不会停掉工作线程启动的子进程**：实测停服务后导出用的 FFmpeg 还在跑。只关这个项目：写进了待办和决策 6.42。
- **实测数字**：4 分钟片段，转录 36 秒、修正转录稿 20 秒、判断剪辑约 26 秒、导出约 28 秒、写笔记约 80 秒；Claude 写笔记时停下，命令行 3 秒内停掉；笔记线程停下后收尾最长约 25 秒（已改为停下时立刻标明）。只关这个项目：写进了决策 6.42 和测试记录。
- **`-n auto` 在负载高的机器上会被系统杀掉整套测试**（退出码 137），`-n 4` 稳定。只关这个项目，暂未写进 `AGENTS.md`，留给主对话判断要不要改那一行。
