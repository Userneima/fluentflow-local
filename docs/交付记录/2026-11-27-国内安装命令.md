# 交付记录：国内安装命令改成从 npmmirror 的发布包取

2026-11-27 · T3 子对话（OpenCode，deepseek-v4.1-flash）· 起因：主对话问「待办中质量这条该如何推进」，王愉超随后定「按国内镜像那条做」

## 1. 改了什么

- 国内一条命令装不再是 `registry.npmmirror.com/fluentflow-local/latest/files/install.sh`（对应用包返回 403，白名单只收 library），改成：读 `latest` 的 `dist.tarball` → 下载整包 → 解出 `package/install.sh` / `install.ps1` → 用 `package/source` 作为 `FLUENTFLOW_INSTALL_SOURCE` 运行。安装脚本和代码都只用这一个包，不探 GitHub。
- 写到的位置：`README.md`（macOS 那条）、`AGENT_INSTALL.md`（macOS 和 Windows 两条，加一句为什么不再按文件取）、`docs/04-维护手册.md`（发版核对和「发到 npm」）、`install.sh` 和 `install.ps1` 开头的用法注释、`scripts/stage_npm_package.py` 的说明。
- 文档：`docs/03-更新记录.md` 把 0.12.0 里没兑现的那条挪到 Unreleased 并按现在的命令重写；`docs/决策记录/7-安装.md` 的现状和 7.7 做法同步，新增 7.20；`docs/01-待办.md` 那条改成「已改好」，另记一条页面更新命令还走 raw 的遗留。
- 测试：`tests/test_stage_npm_package.py` 新增一条，守 README、AGENT_INSTALL、两个安装脚本开头不再出现 `/files/install` 地址、都指向 `dist.tarball` 和 `FLUENTFLOW_INSTALL_SOURCE`。

## 2. 怎么验证的

验收命令（在本机照 README 那条命令跑，只多加了两个跳过项）：

```
PATH=<挡掉 github 的 curl 包装>:$PATH FLUENTFLOW_INSTALL_DIR=/private/tmp/ff-cn-test/install \
  FLUENTFLOW_DATA_DIR=/private/tmp/ff-cn-test/data FLUENTFLOW_LOCAL_PORT=8127 \
  bash -c '<README 那条命令，install.sh 后加 --skip-model --skip-desktop>'
```

- 第一次：退出码 0，代码从包里的 `source` 放到安装目录（0.12.0），服务在 8127 起来，`/health` 报 `edition: local`，MCP 自检通过；整份日志没有一处访问 GitHub（包装脚本一次都没被触发），Python 用本机的 3.14、FFmpeg 用本机已装的。
- 第二次（同一条命令）：报「0.12.0 不比包里的旧」，依赖 27 毫秒核完，服务照常在，不重复安装。
- 本机另跑：`pytest tests/test_install_places.py`（78 过、20 跳过）、`pytest tests/test_stage_npm_package.py`（7 过）。
- 跑完还原：OpenCode 的 `opencode.json` 被安装程序改写过（原本没有 FluentFlow 条目），已 `git checkout` 还原；`~/.claude/skills/fluentflow` 原来没有，删掉；`~/.codex/skills/fluentflow` 原来指向本仓库，已改回；Claude Code 和 Codex 的 MCP 注册核对过没变（`~/.codex/config.toml` 的指纹、`claude mcp get` 的输出和跑之前一致）；测试服务停掉，临时目录删掉。

## 3. 没做、没验证的

- Windows 实机没跑：命令只按 Windows PowerShell 5.1 的写法核对过（`iex (Get-Content -Raw -Encoding UTF8)` 避开执行策略和编码，`tar` 用系统自带的，安装脚本里本来就用它解包）。
- 真实国内网络下的下载速度和镜像切换没测：这次靠在本机挡掉 GitHub 模拟，网速是正常的。
- 装完没有真转录一条录像（跳过了转录模型）。
- 没另派 Codex 审查：这次改动是文档和注释加一条测试，推送按平常流程。
