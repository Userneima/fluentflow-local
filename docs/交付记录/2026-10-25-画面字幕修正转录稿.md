# 按画面上的字幕修正转录稿

2026-10-25 · 子对话交付 · 决策 4.10 · 直接推 main

## 交付单

### 1. 改了什么

- 新模块 `backend/core/subtitle_correction.py`，转录、标说话人之后，翻译和写笔记之前跑：
  - 判断有没有烧进画面的字幕：均匀抽最多 10 句，各截一帧画面下方三分之一，用 macOS 的文字识别读出来，和那几秒前后三句转录对得上（按字符顺序重合六成以上）的有 3 句就算有字幕，否则整步跳过。
  - 写笔记用的那个文字模型（没有 Key 时用 Claude，和英文字幕翻译选法一样）分段通读转录稿，挑出可能听错的词，每处要求原样出现在那一句里。
  - 每处在那句之内截 1 到 3 帧，再加前后各 2 秒两帧（字幕和转录会差几秒），重复的帧只读一次；只留和附近转录对得上、又和这一句本身有重合的字幕行，识别乱码和视频底部的章节栏都进不去。
  - 模型看着这句、前后句和字幕行决定换不换。程序再卡一道：被换的文字必须在原句里，新写法必须在某行字幕里（大小写、空格、识别常混的 l/I、0/O 不计）。
  - 改动写进 `raw_segments`、`display_segments`、`transcript_text`，`stt_raw_segments` 不动；每处的记录（原词、新词、在句中的位置、时间、依据的字幕行、改前改后整句）存在 `subtitle_corrections`，整步的情况存在 `subtitle_correction`（跑没跑、跳过原因、各阶段用时）。
- `backend/core/media_job.py`：接进处理流程，进度显示「正在对照画面上的字幕核对人名和术语…」；记事件 `subtitle_correction_completed` / `_failed`。任何失败都不让任务失败。
- `backend/core/survey_cut.py`：先转录再剪的流程，把改动记录的时间也换到剪后视频的时间上，撤回时能按时间找到那一句。
- 撤回：`GET /agent/v1/tasks/{id}/subtitle-corrections`、`POST …/subtitle-corrections/revert`，MCP 工具 `list_subtitle_corrections`、`revert_subtitle_corrections`。撤回按记录的位置把新词换回原词，同一句改了两处时从后往前撤；撤回后重写字幕文件，产出文件夹经结果保存时的监听跟着更新；已写好的笔记不重写。
- 默认开，`FLUENTFLOW_SUBTITLE_CORRECTION=off` 关掉。
- 文档：决策记录 4.10 和第四节现状、更新记录、待办「效率」一条（太慢）、README（画面字幕一段和「什么会离开这台电脑」）、`agent/skills/fluentflow/SKILL.md`、维护手册环境变量表、关于页（转录稿会发给模型服务商）。
