# 已知问题（2026-10-07 审查）

来源：2026-10-07 对 0.5.0 之后代码的复审、一次隔离环境真实任务、以及导出与接口部分的审查。修好一条就从这里删掉一条，并在 `docs/changelog.md` 记一笔。

## 导出与笔记质量

- 下载 Markdown 时截图是本机相对地址，在其他编辑器里全是坏图；导出 Word 时截图固定 16:9，竖屏截图被压扁。
- 「更换提示词」和笔记模式只影响文本模型的笔记，对 Claude 写的画面笔记不起作用，界面没有说明。
- 字幕按剪后时间轴生成，却和「原视频」放在同一个下载菜单里；对已自动剪过的任务再手动剪一次，字幕和笔记的时间点会对不上且不报错（MCP 的 `debreath_task` 能触发）。

## 稳健性与数据

- 笔记等 Claude 名额时在默认线程池里阻塞，批量处理大量短文件时会占满线程池，拖慢上传和流水线。
- 写笔记超过整体时限时，已经写好的稿子会被整份丢弃，应保留现有稿子、只跳过后续润色。
- 笔记写作中，任务快照里「AI 笔记生成」一步已标为完成；`metadata` 里的转写状态停在 `preparing_audio`；排队返回的位置总是 1/1；部分事件的 `route` 写成 `/process`，纯音频任务的 `pipeline_mode` 为 `audio_video`。
- 笔记等待 Claude 期间允许对同一任务手动去气口，两边整份写回结果时可能互相覆盖。
- 在等名额时取消任务会漏掉一个并发名额。
- 任务 id 已在运行时再次提交，会让队列断链。
- 局域网模式下，网页的写操作会被 Origin 检查拒绝，网页实际只读。
- 本机同一路径的任务，剪后文件在原文件旁和任务目录里各存一份。
- `distribution/local.env.example` 列着几个后端已不再读取的环境变量。
