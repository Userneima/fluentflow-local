来源：2026-10-08 对 0.6.0 的四路复审：代码复审（v0.5.0..v0.6.0）、隔离环境真实任务（本地视频、抖音、B 站、重复提交、重试）、设置页与界面审查、启动器与文档审查。修好、不做或暂缓一条，就从这里删掉，在 `docs/decisions.md` 记下为什么，用户感觉得到的变化再在 `docs/changelog.md` 记一笔。「实测」指真实跑过；其余为读代码得出。

## 安装与启动（未在 Windows 实机验证）

- Windows 启动器很可能一启动就闪退：`$ErrorActionPreference = "Stop"` 下，uvicorn 写到 stderr 的第一行会被 PowerShell 5.1 当成致命错误；`.cmd` 没有 `pause`，看不到原因。
- Windows 卸载脚本读错了 `/health` 字段，认不出正在运行的服务，会在服务运行中删虚拟环境。
- 启动过程中再点一次图标会起第二个启动流程，两个 pip 可能同时升级 yt-dlp；yt-dlp 升级按总时长强杀 pip，可能装坏一半；升级的那几秒里开始的链接下载会被报成「yt-dlp 没装」。
- 国内用户安装时设的 `PIP_INDEX_URL` 不会保存，之后每天的 yt-dlp 自动更新都去连 pypi.org，静默失败。
- 端口读法在启动器、卸载脚本、Windows 之间不一致；前端没构建时提示的 `npm run build:frontend:local` 不存在；Windows 脚本全是英文提示。

## 计划中（2026-10-13 后端效率复盘，王愉超已定）


- 笔记里的截图只放值得看的，并裁到有用的那一块（王愉超 2026-10-14 定）。现状：录屏和会议抽出来的帧是整个桌面，Claude 按「这一刻屏幕上是表格」去引用，不判断截出来能不能看清。2026-10-14 那份冲刺规划会的笔记放了 4 张整屏截图：表格那张里的字读不出、还被弹窗挡住；Slack 那张要说的内容正文已经写了。手工复核后删掉 2 张，另 2 张裁剪后保留，PDF 从 2.5MB 降到 0.8MB。要做：
  - 写笔记时 Claude 对每张想引用的截图判断：正文说不清、看图才明白的才放（比如看板怎么分区）；正文已经写清的，或裁出来仍读不清、缺了关键一列的，不放。
  - 放的截图给出要裁的区域（只留共享的页面、窗口或其中一块），导出时按区域裁剪；裁出来的图较小时按原大小显示，不拉满整页宽。
  - 图放在它说明的那段旁边，图下面一行图注，写看这张图能看到什么。
- 拿不准的词按笔记写法放进「存疑」，不当事实写进正文。现状：同一份笔记里「他提到相关模拟已经基本做完」，对应的转录是「这个你给我们拉模拟做的差不多了」，「拉模拟」读不通，大概率是语音识别听错的工具名，却被写成了事实。要做：读不通、像是听错的人名、工具名、数字，正文写「（转录读不清，见存疑）」，在「存疑」里列出原话和可能的意思。
- 提升文字模型（DeepSeek、OpenAI、通义千问）写的笔记质量（王愉超 2026-10-13 定）：Claude 不可用或写失败时由它兜底，这条路线保留，质量差就改进它。做法：拿张和训练营的视频，同一段分别让 Claude 和文字模型写，对照找差距，再改文字模型那条路的写法和查漏。
- 提交时就检查时长上限（默认 4 小时）。现在要等剪完、转录前才发现超长，白等一轮剪辑。超过 4 小时的录像少见，排在后面。
- 说话人区分换成更轻的本机方案：现在要装 pyannote，它带上整套 PyTorch，几百 MB；sherpa-onnx 安装包约 4.5MB，用同类模型。先在单独的临时环境里拿一段几分钟、多人发言的会议片段测准确度和耗时，效果好再接进产品，替换 pyannote。
