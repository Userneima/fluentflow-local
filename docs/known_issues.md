# 已知问题（2026-10-08 复审 0.6.0）

来源：2026-10-08 对 0.6.0 的四路复审：代码复审（v0.5.0..v0.6.0）、隔离环境真实任务（本地视频、抖音、B 站、重复提交、重试）、设置页与界面审查、启动器与文档审查。修好一条就从这里删掉一条，并在 `docs/changelog.md` 记一笔。「实测」指真实跑过；其余为读代码得出。

## 安装与启动（未在 Windows 实机验证）

- Windows 启动器很可能一启动就闪退：`$ErrorActionPreference = "Stop"` 下，uvicorn 写到 stderr 的第一行会被 PowerShell 5.1 当成致命错误；`.cmd` 没有 `pause`，看不到原因。
- Windows 卸载脚本读错了 `/health` 字段，认不出正在运行的服务，会在服务运行中删虚拟环境。
- 启动过程中再点一次图标会起第二个启动流程，两个 pip 可能同时升级 yt-dlp；yt-dlp 升级按总时长强杀 pip，可能装坏一半；升级的那几秒里开始的链接下载会被报成「yt-dlp 没装」。
- 国内用户安装时设的 `PIP_INDEX_URL` 不会保存，之后每天的 yt-dlp 自动更新都去连 pypi.org，静默失败。
- 端口读法在启动器、卸载脚本、Windows 之间不一致；前端没构建时提示的 `npm run build:frontend:local` 不存在；Windows 脚本全是英文提示。

## 计划中（2026-10-13 后端效率复盘，王愉超已定）


- 提交时就检查时长上限（默认 4 小时）。现在要等剪完、转录前才发现超长，白等一轮剪辑。超过 4 小时的录像少见，排在后面。
- 说话人区分换成更轻的本机方案：现在要装 pyannote，它带上整套 PyTorch，几百 MB；sherpa-onnx 安装包约 4.5MB，用同类模型。先在单独的临时环境里拿一段几分钟、多人发言的会议片段测准确度和耗时，效果好再接进产品，替换 pyannote。

## 计划中（按 2026-10-09 定的顺序）

- 写笔记后加一轮核对：让 Claude 按要求文件里能逐条判断的硬规定再查一遍并修改。先用实测的 10 段素材对比「只用要求文件」和「要求文件加核对」两版的笔记和费用，再决定做不做。
- 双击安装包：打包 Python、转写模型和前端，签名后可以直接双击安装，免去终端、Homebrew 和手动设镜像。
- 第一次填 Key 引导里的费用：现在只写「按用量计费、以官方价格页为准」。要给出实际估算，需要先在写笔记时记录每次用了多少 token，再按官方单价算。
- 批量提交上限（默认一次 5 个文件）挪进设置页或调大默认值。
- 结合画面写笔记的提示词写死为「课程或讲座录像的学习笔记」，会议录像会被套成学习笔记结构；是否按录像类型切换，等目标用户定下来再做。

## 暂缓（2026-10-14 王愉超定）

- 同一个视频重复处理时，给各个剪后版本标清差异、提醒删除对比版本。暂缓的理由：重复版本几乎都来自对话拿原片做测试，现在测试一律用复制到临时目录的片段；每一版的剪辑设置（帧率、处理偏好、电脑占用）已经记在任务里。等用户真要拿同一个视频剪两版对比时，再按那时的需要做。
