# 已知问题（2026-10-07 审查）

来源：2026-10-07 对 0.5.0 之后代码的复审、一次隔离环境真实任务、以及导出与接口部分的审查。修好一条就从这里删掉一条，并在 `docs/changelog.md` 记一笔。

## 从链接获取视频（2026-10-08 实测与审查）

实测指用产品自己的下载函数联网跑过；其余为读代码得出。

- 配了浏览器登录态但读不到（macOS 27 下的 Chrome）时，B 站和 YouTube 链接全部失败（实测）：`--cookies-from-browser` 加在每次 yt-dlp 调用上，读不到就直接退出；只有抖音有备用路。B 站还会提示「去设置里开浏览器登录态」，正好说反。
- B 站普通视频解析成功也下载不下来（实测）：选中的 DASH 地址在 PCDN 的非标准端口和不在白名单的域名上，`download_file` 只放行 80/443。交给 yt-dlp 自己下载并限制在 720p 可以下载成功。
- 抖音约三成下载随机失败（实测）：第三方解析给出的地址会跳转到百度 CDN，跳转校验按域名拒绝。
- B 站会员内容只下到试看片段却报成功（实测）。
- 抖音图文、已删除视频、第三方解析偶发失败，都被提示成「读不到 Chrome 登录」（实测）。
- `iesdouyin.com` 链接被判为不支持（实测）；`v.douyin.com` 不带 `https://`、`bili2233.cn` 短链也识别不到；链接后紧跟的中文会被吞进链接；粘贴多个链接时只取第一个。
- 下载中断留下的半截文件，之后重试会被当成完整视频复用：第三方解析和直链这条路直接写最终文件名。
- 同一链接同时提交两次会互相写坏文件。
- 抖音用 yt-dlp 解析成功后，下载阶段又调用一次 yt-dlp，不重试也不回退，报错是英文原文。
- 格式选最高分辨率：B 站登录后或 YouTube 容易超过链接下载的 600MB 上限（本地上传上限是 2048MB），超限时 yt-dlp 路线提示「yt-dlp 没有写出视频文件」（实测），建议「压缩或拆分文件」对链接也做不到。
- yt-dlp 在 Apple 芯片 Mac 上被锁定文件锁在一个版本，用户没有更新途径，平台一改版就整批失效。
- 重试链接任务不带浏览器登录设置，也漏了其他选项；重试用的是截到 200 字的分享文本，长分享文本里的链接会丢；后端 `retry_task` 对下载阶段就失败的链接任务报「原始录音已按保留策略清理」。
- YouTube 失败原因（机器人验证、年龄限制、私享）被换成笼统的「暂时无法解析」；B 站任何失败都说「需要登录」。
- YouTube 没有合并格式时走了 B 站专用的下载合并路径，进度文案写「B 站」，请求带抖音的 Referer。
- 下载进度在 yt-dlp 路线上一直停在 10%。
- 设置页选的浏览器登录态只存在浏览器本地，AI 工具（MCP）提交的链接用不上。
- 链接下载不进串行队列、没有并发上限，批量提交时会同时下载、并占用默认线程池。
- 输入框写「视频或播客链接」，但播客链接和 .mp4 以外的直链都不支持。
- 小问题：抖音标题里的话题标签变成一串词；直链标题是哈希值；没有登录态时抖音链接先让 yt-dlp 重试三次，固定多花十几秒；超过时长上限要等下载完、排完队才发现；代码注释说第三方解析默认关闭，实际默认开启，界面上也没有开关。

## 导出与笔记质量

- 飞书导出时笔记里的本机截图很可能丢失（默认的官方转换路线和 lark-cli 路线都不上传本机图片），前端仍提示成功。未用真实飞书账号验证。
- 飞书导出的各类失败几乎都被诊断成一句「飞书导出失败。」，与 README 的说法矛盾；提示里提到的设置项名称已过时。
- 默认的飞书应用路线把文档建在应用空间，没有给用户加权限的步骤，用户可能打不开。未验证。
- 下载 Markdown 时截图是本机相对地址，在其他编辑器里全是坏图；导出 Word 时截图固定 16:9，竖屏截图被压扁。
- 「更换提示词」和笔记模式只影响文本模型的笔记，对 Claude 写的画面笔记不起作用，界面没有说明。
- 字幕按剪后时间轴生成，却和「原视频」放在同一个下载菜单里；对已自动剪过的任务再手动剪一次，字幕和笔记的时间点会对不上且不报错（MCP 的 `debreath_task` 能触发）。
- 每次导出到飞书都新建一个文档，导出过的链接不保存在任务里；分批写入中途失败会留下半截文档。

## 稳健性与数据

- 笔记等 Claude 名额时在默认线程池里阻塞，批量处理大量短文件时会占满线程池，拖慢上传和流水线。
- 写笔记超过整体时限时，已经写好的稿子会被整份丢弃，应保留现有稿子、只跳过后续润色。
- 笔记写作中，任务快照里「AI 笔记生成」一步已标为完成；`metadata` 里的转写状态停在 `preparing_audio`；排队返回的位置总是 1/1；部分事件的 `route` 写成 `/process`，纯音频任务的 `pipeline_mode` 为 `audio_video`。
- 笔记等待 Claude 期间允许对同一任务手动去气口，两边整份写回结果时可能互相覆盖。
- 在等名额时取消任务会漏掉一个并发名额。
- 任务 id 已在运行时再次提交，会让队列断链。
- 局域网模式下，网页的写操作会被 Origin 检查拒绝，网页实际只读。
- 本机同一路径的任务，剪后文件在原文件旁和任务目录里各存一份。
- `distribution/local.env.example` 列着几个后端已不再读取的环境变量。
