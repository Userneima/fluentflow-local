# 产品审查：眼下最该做什么（2026-11-21）

按 product-lens 做的一次整体审查。用户只有王愉超本人；优先顺序沿用待办开头他定的「质量 → 可靠 → 省心 → 效率 → 成本 → 装得上」。

## 事实（查自本机任务库和仓库，2026-11-21）

- 任务量：9 月 91 条、10 月 133 条、11 月（到 21 日）68 条。
- 11 月的 68 条里，47 条是 50 MB 以下的短视频，其中 37 条提交时就不剪辑，在 FluentFlow 里写了笔记的只有 3 条：大多是 agent 拿去转写、在别的项目里用（抖音卡片调研、游戏制作经验库等）。长录像（课程、周会）7 条，写笔记的主要是这些。
- 11 月失败 9 条：没有人声 3 条（已改为读画面文字，0.11.0）、同一条小红书视频下载被拦 3 次、平台拒绝或断线 3 条。
- 笔记反馈记录（`record_note_feedback` 写的 `feedback.json`）：一条都没有。他对笔记的纠正走的是对话，再由 agent 改写法、记进决策记录。
- 笔记质量考题（`private/笔记考题/`，五份）：最近一次整体评分是 10-18，之后 11-06 为合并写法补跑过一条课程。11-14 改成「随看笔记完全按讲的先后写」（决策 6.72）没有重跑考题。
- 10-13 定的「查漏」下一步（他逐条对照张和训练营录像和笔记）没有记录显示做过。
- 王愉超 2026-11-21 说：第三课（0707）的笔记他已经逐篇确认过，没问题。确认的是产出文件夹里现在那份（最后一次由 agent 写入并改字在 11-14 13:09）。这是目前唯一一条来自真实阅读的质量结论；罗福莉访谈那份考题他也早已校正完（10-18 定稿）。
- 待办里「质量」一节是空的，「可靠」两条都是停服务、发飞书被打断这类少见情形。最近两周约 100 次提交，主要在飞书同步、编辑页跟随、剪辑信任和代码清理。

## 判断

1. 质量排第一，但现在没有来自真实使用的质量信号（让主要任务变差）。待办的质量一节空着，是因为没有东西在量，不是因为量过没问题：考题只在改写法时偶尔跑，真实读笔记时发现的错漏没有落进产品。最近一次改写法（按讲的先后写）没有过考题，可能让笔记出现重复、同一结论散在几处。
   - 动作：把五份考题在现行写法上跑一遍（走订阅，每条约 8 分钟），和 10-18、11-06 的结果比，差 3 个百分点以内不算变化；以后改写法 skill 的提交必须附这次对照。
   - 动作：他下次拿笔记学的时候，看到的错和漏由 agent 当场用 `record_note_feedback` 记下（带原文片段），攒到同一类出现两次再改写法。这比再做合成评测更接近真实质量。
2. 实际用量已经偏向短视频转写，开发投入还在长录像（只是没那么好）。短视频这条路现在没有明显痛点，失败都是个案；但它们的等待时间、下载成功率没人看过。动作：下次批量跑短视频时，从任务包的各环节用时里看一眼下载和转写各占多少，有明显瓶颈再进待办；没有就不动。
3. 「对外」这件事没有定（只是没那么好，但会改方向）。仓库公开、发版本、写进简历，而「装得上」整类挂在「等前提」。我的倾向：维持挂起，除非求职要演示给别人装；真要演示，最少要在一台全新 Mac 上照 `AGENT_INSTALL.md` 让一个干净的 agent 装一次。这件事归他定。

## 不确定的地方

- 「笔记质量没退步」只能靠考题判断，考题同一输入跑两次结果会有浮动，单次结果只代表那一次。
- 短视频的用量是从文件大小和提交参数推的，没有逐条核对用途。
