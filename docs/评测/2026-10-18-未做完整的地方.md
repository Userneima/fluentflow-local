# 处理流程里没做完整的地方（2026-10-18 只读排查）

范围：提交 → 转录 → 先通查再剪 → 处理说明 → 写笔记 → 查漏 → 原片旁的产出文件夹 → 导出。只读代码和文档，没有跑任务、没有重启服务。`docs/01-待办.md` 里已有的（防止修改被覆盖八条、任务「完成」按步骤算和重启续接、文字模型对照实测、会议待办写名字）不重复列。

排序按用户受的影响。每条都按 file:line 核对过。大小：小 = 半天内，中 = 一两天，大 = 要设计。

## 1. 处理说明里改判后，没有 Claude 时文字模型直接覆盖笔记，不留旧版

- **在哪**：`backend/routers/local_job_debreath.py:237-239` 改判重新导出后调用 `local_intake_flow.write_note`。没有 Claude 时走 `local_intake_flow.py:322-324` → `_write_text_note_instead`，在 `local_intake_flow.py:478-488` 用新笔记整份替换，没有调用 `record_replaced_note`。没有任何 Key 时，`local_intake_flow.py:416-426` 把笔记标成「跳过」，旧笔记却原样留着，而它对应的是改判之前那版剪辑的时间。
- **缺什么**：只有 Claude 那条路会把被替换的笔记存成可恢复的一版，文字模型这条路没有。
- **谁会碰到**：用文字模型（现在首推的通义千问）或让 agent 写笔记的用户，在处理说明里点「这段不该剪」「这段应该剪掉」之后。手改过的笔记、Obsidian 收回的修改、agent 写的笔记都会被一篇文字模型笔记盖掉，找不回来。这碰到了「不动坏用户改过的东西」这条底线。待办「防止修改被覆盖」第 3 条只说了网页「重写笔记」，没有这条路。
- **大小**：小（补 `record_replaced_note`；没 Key 时不把状态标成跳过，并说明笔记对应的是旧剪辑）。

## 2. 文字模型写长录像时，写法要求只在查漏补写时用到

- **在哪**：转录超过 2 万字（`backend/core/ai_config.py:37`，大约一小时以上的录像）时走按章写（`ai_summarizer.py:813` → `_run_chapter_coverage_mode`，`ai_summarizer.py:1148`）。逐章写和统稿用的是固定提示词 `_CHAPTER_NOTE_SYSTEM` 和 `_CHAPTER_STYLE_SYSTEM`（`ai_prompts.py:269-291`，在 `ai_summarizer.py:1165-1167, 1212, 1226` 用到）。包含会议写法、用户在设置里换的提示词、校正文档的那份 `prompt`，只在查漏和补写时用上（`ai_summarizer.py:1243, 1246`）。
- **缺什么**：长录像的初稿看不到会议写法（决定、待办、用名字称呼）、用户自己的提示词，也看不到系列校正文档。
- **谁会碰到**：用文字模型写一小时以上会议或课程的用户，每一篇都会碰到。会议笔记没有「决定」「待办」，听错的人名照旧写错；在设置里换了提示词，长录像上也看不出变化。
- **大小**：中（把用户提示词里的写法要求和校正文档带进逐章写和统稿，再在周会考题上比一次）。

## 8. Windows 上不防睡眠、不用显卡编码、不出压缩版

- **在哪**：防止闲置睡眠只在 macOS 上做（`backend/core/local_keep_awake.py:39-41`，`sys.platform != "darwin"` 时什么都不做）。硬件编码只认 `hevc_videotoolbox`（`device_profile.py:85`，`compress_media.py:73, 87`），NVIDIA 的编码器从来不试；于是 `compress_media.py:123-124` 在 Windows 上总是跳过「没剪气口的压缩版」（决策 3.15）和「剪不动时另存的压缩版」。压缩版做没做成、为什么没做，页面和 agent 都看不到：`compressed_copy` 只写在 `local_intake_flow.py:216`，前端和任务包都不读它。
