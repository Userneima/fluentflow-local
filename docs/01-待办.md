# 可靠

## 停服务时，写笔记里正在路上的那一次请求要等它回来（2026-11-06 实测）

- 修正转录稿已经不等了（决策 6.63，0.9 秒退出）。写笔记、查漏、剪辑判断那几处的请求是在不能丢下的线程里发的，停服务时进程要等正在路上的那一次请求回来才退出：实测查漏那次让退出等了 25 秒（假模型每次答 25 秒；真模型一次写正文可能要一两分钟）。回答会存下，接着做时不重付，只是退出慢。
- 做法：发请求的线程都改成服务退出时可以丢下的那种（`model_usage.stoppable_map` 的做法），或停服务后过几秒强制退出。强制退出前要确认那一刻没有正在写的笔记文件。
- 重做不需要原片：只影响以后的任务。

## 发飞书在传截图前被打断，续上后截图不补（2026-11-06）

- 决策 6.63：被打断的导出再导出时写进同一篇飞书文档，不再新建；但正文已经写进去、截图还没传的，续上时章节对比没有变化，截图不会补传，结果里只写一句「截图没有补上」。要补得按截图标记把缺的图逐张插回（`_insert_images` 那套定位），或删掉这篇自己刚建的文档的正文重写。没有实测过真飞书文档，动手前先在测试文档上试。
- 重做不需要原片：只影响以后的任务。

# 省心

## 本地字幕文件原地出笔记（2026-10-29 实测）

- 只有 srt、没有视频的文件，现在只能当转写稿交（`submit_transcript`），任务不知道字幕在哪个文件夹，笔记不会放到字幕旁边，也不会和 Obsidian 双向同步。10-29 整理「1.短视频」时有 3 份是 agent 手动把笔记写进去的。
- 要加一个像 `submit_local_media` 那样按路径原地交字幕文件的入口：产出文件夹、标记文件、同步都照本地视频的做法走。

## agent 补几处转录修正时只能按页取材料（2026-11-05 第四课收尾，11-14 定暂不做）

- 补 4 处被拒的转录修正，MCP 只能按页取材料（一页 300 句），为改 4 句要把几页全文读进对话；agent 当时直接在命令行调了后端的 `agent_correction.save`，在另一个进程里存，产出文件夹没跟上，又手动补了一次 `output_folder.sync`。笔记那一半已由 `replace_note_text` 解决（按原文定位，可以多处一起改）。
- 要做的：修正工具支持按句子编号只取那几句和前后几句，带每句的版本号存回。
- 暂不做的原因（2026-11-14 王愉超定）：只出现过一次，影响的是 agent 多花一些额度，不影响产出；倾向等再碰到一次，或改正流程本来要动时一起做。

## agent 遇到的阻碍

agent 绕开 FluentFlow 的 MCP 工具时记在这里（全局规则「绕了路就当场说，并记下来」），每周代码大扫除时汇总排序给王愉超挑。

- **agent 用 save_agent_note 存的笔记没落进输出文件夹**（2026-11-10）：一份本机录屏走 agent 剪辑、agent 校正、agent 写笔记，任务报 done，`output_folder` 里却只有剪后视频和过程文件，`pdf_path`、`md_path` 都是空的，而 `export_result` 的说明写着输出文件夹里的 PDF 和 md 会自动保持最新。agent 只好用 `export_result target=pdf` 导到这个文件夹再改名，md 从 artifacts 目录手抄过去，图片链接（`/jobs/...` 接口地址）手改成本地截图路径。之后用 `replace_note_text` 改字时，输出文件夹的 md 和 PDF 自动刷新了（图片也成了相对路径），所以缺的只是 `save_agent_note` 第一次保存时的那次写出。建议：`save_agent_note` 保存后同样触发输出文件夹的写出。
