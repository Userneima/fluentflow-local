## 第三批：用户自己的 agent 来判断剪辑（2026-10-16 定方向）

主路是用户在自己的 agent（Claude Code、Codex、WorkBuddy……，彼此并列）里用 FluentFlow，判断剪辑、整理说明、写笔记都用这个 agent 的订阅（王愉超 2026-10-16 定）。接入靠 FluentFlow 已有的 MCP（`scripts/fluentflow_mcp_server.py`，agent 写笔记已经这样做：取材料、存笔记），不为每种 agent 单独写命令行接入。

1. **王愉超用 Codex 试一次**：从 Codex 里通过 MCP 提交一条录像、写笔记，看能不能顺利跑完。
2. **加剪辑判断的 MCP 工具**：
   - 取判断材料：时间线（转录稿、长空白、画面在不在动），拿不准的长空白截图的路径，agent 自己打开看；
   - 交回剪辑决定：保留哪些空白、去掉哪些说话段、各自理由。FluentFlow 收到后导出视频、整理处理说明；

# 效率与方便

## 第四批：各步只写自己那一格，导出和写笔记同时跑（2026-10-16）

- 现在一个任务的结果存成一整份，导出、整理处理说明、写笔记每一步都「整份取出、改自己那部分、整份放回」，两步同时跑时后放回的会把先放回的冲掉，所以靠「禁止同时跑」防丢数据。
- 做法：加一个只改记录里指定几项的写法（数据库支持），这三步改用它，各写各的那一格。之后导出视频和写笔记可以同时进行，长录像每条约省 6 分钟（张和 58 分钟那条估算：等 Claude 写正文的 6.5 分钟可以和导出重叠），也不再靠一条禁令防丢数据。
- 排在第三批之后：第三批会改变剪辑结果，这一条只影响快慢。第一批的重复受理问题先单独修，不等这次改造。
