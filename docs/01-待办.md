agent 绕开 FluentFlow 的 MCP 工具时记在这里（全局规则「绕了路就当场说，并记下来」），每周代码大扫除时汇总排序给王愉超挑。

- **Windows 安装检查的临时 workflow 每次要从删掉的提交里捞回来**（2026-11-25，第 5 批）：维护手册让检查脚本只放在临时分支、跑完删掉，这次只好用 `gh api repos/.../contents/...?ref=<旧提交>` 把 11-21 那份取回来再改，三轮里有两轮停在检查脚本自己的写法上（`.env` 里的值带引号、`claude mcp get | Select-Object -First 3` 截断后退出码不对）。改法：把这份检查（装到 D 盘、自愈、失败更新换回、更新、卸载、按锁定文件跑测试）放进 `.github/workflows/`，只留手动触发（`workflow_dispatch`），不进每次推送的 CI；要他点头，因为会多一个 Actions 入口。
- **Mac 的安装、更新、卸载没有不碰真实安装的测法**（2026-11-25，第 5 批）：`install.sh` 会注册 Claude Code、Codex 的工具、起 8000 端口、建桌面图标，直接跑会盖掉王愉超自己的安装；这次手写了一个包装：`env -i` 另设 `HOME`、`CODEX_HOME`，`FLUENTFLOW_LOCAL_PORT=8019`，`FLUENTFLOW_INSTALL_SOURCE` 指向本机构建好的发布包，`--skip-model --skip-desktop`。查出了 bash 5 读代理中断安装、换回后服务不起、卸载漏删两处，值得固定下来。改法：把这个包装做成 `scripts/` 下的一个开发用脚本（装、失败更新、更新、卸载四步，结束时报剩下什么），维护手册的发版检查里加一行。
- **本机没有 PowerShell，Windows 脚本只能靠 GitHub 的 Windows 机器验**（2026-11-21，装进一个文件夹那次）：每改一处 `.ps1` 就要推临时分支、等 15 到 20 分钟，七轮里有三轮停在检查脚本自己的问题上（临时 workflow 里的中文在 Windows PowerShell 里读成乱码、robocopy 成功也返回 1、npm 的提示被当成错误）。改法：Mac 上装 PowerShell（`brew install powershell`，开发用，要他点头）先在本机做语法检查和能跑的片段；临时 workflow 的步骤一律先设 `$ErrorActionPreference = "Continue"`，判断只用英文和文件存在与否。
- **服务日志没有时间**（2026-11-25，长录像提取音频）：`~/Library/Logs/FluentFlow/local.log` 只有 uvicorn 的请求行、不带时间，查 10-27 那次提取音频为什么比同版本慢 3 倍时，没法知道当时机器上同时在跑什么，只能写「最可能是机器忙，没法确认」。改法：日志行带上时间；事件库的 `audio_extracted` 顺带记一下当时的系统负载（`os.getloadavg()`），慢的时候能直接看出是不是被挤。没修，留给大扫除排序。
- **测试副本里假模型写不了笔记**（2026-11-25，实测「学完了」）：按 `--fake` 起的副本，没有模型 Key，用 `submit_transcript(intelligence="fluentflow")` 交的任务笔记失败（「DEEPSEEK_API_KEY 未设置」），假模型没接上这一步；只好改成 `intelligence="agent"` 再手写一篇存进去。改法：设了 `FLUENTFLOW_FAKE_MODEL` 时，文字模型这一步不查 Key、直接由假模型回答。没修，留给大扫除排序。
