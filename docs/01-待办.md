# 可靠

## 停服务时，修正转录稿这一步要做完这一轮才退出（2026-10-26 实测）

- 停服务时导出剪后视频的 FFmpeg 已经跟着停、被打断的那一步重启后接着做（决策 6.43）。剩下一处：「修正转录稿」（按画面字幕修正、词表纠正）在自己的一组线程里截图、读字、调模型，这些线程不认停止信号。2026-10-26 在这一步停服务，进程等了 165 秒才退出；那一轮已经发出的模型调用照样做完，重启后这一步重做，这部分等于付了两次。用户点「停下这一步」时也一样要等它做完这一轮。
- 做法：让这一步的线程池也带上「这是哪个任务的活」（`task_stop.bound`），截图和调模型之前先看这个任务是否已被要求停下；订阅命令行走 `task_stop.track` 就会被停掉。
- 重做不需要原片：只影响以后的任务。

# 省心

## 右侧笔记跟着播放进度走（2026-10-23 王愉超定）

- 要什么：播放到哪一节，右侧笔记就高亮那一节并滚过去；有「跟随播放」开关；用户在笔记里滚动或打字时暂停跟随；每节标题旁显示时间，点了视频跳过去。对到章节，不对到句子（笔记按主题重组过，不按录像顺序）。
- 做法：每一节配上对应的录像时间段，由模型读笔记章节和带时间的转录稿给出（不按关键词匹配，笔记是改写过的）；对照表存在任务数据里，不写进 md，Obsidian 和飞书那两份不受影响；新笔记在存好后另调一次模型给出（不改写笔记的提示词），已有笔记第一次打开时补一次；章节标题改了就重对那一节。一节来自多处时跳到主要那一段。
- 第一步验证已做（2026-10-23，决策 6.37）：两条录像 132 节，抽查 19 节全对，起点早 0 到 15 秒。对照表和建议的数据格式在[方案](方案/2026-10-23-笔记跟随播放对齐验证.md)。
