## Windows 安装：整个产品装进一个选定盘的文件夹、国内网络全程有镜像、卸载交给 agent 也能做（2026-11-21 他朋友装时卡住，他定发 0.11.0 后做）

**装到一个文件夹**（他定：整个产品放到一个空置盘，模型和产品放一起）
- 现在程序（`%USERPROFILE%\fluentflow-local`）、数据目录（`%APPDATA%\FluentFlow`，含镜像下载的 FFmpeg）、转录模型（用户目录下的 huggingface 公共缓存，两三 GB）、链接下载（「视频」文件夹）都在 C 盘；前两个能用 `FLUENTFLOW_INSTALL_DIR`、`FLUENTFLOW_DATA_DIR` 改，安装流程不问，转录模型没有对应设置。
- 要做的：`install.ps1` 开头看各盘剩余空间，有别的盘时由 agent 问装到哪个盘（推荐剩余最大的），代码、Python 环境、数据、FFmpeg、转录模型、下载都放进那个盘的 `FluentFlow` 一个文件夹，位置写进 `.env`，以后启动照样读到；只有 C 盘时照旧不问。winget 装的 Python 仍在 C 盘。
- 数据目录只写在 `.env` 时，安装脚本（下载 FFmpeg、Node.js）、卸载脚本和启动前检查只看环境变量，会用默认目录，服务却读 `.env` 用另一个（2026-11-21 推送审查查出，Mac 同样）。写进 `.env` 之前先让这几处和服务按同一套规则读。
- 先实测：转录模型位置写进 `.env` 能否在 huggingface 读取它之前生效；在 GitHub 的 Windows 机器（有 C、D 两个盘）上跑一键安装到 D 盘。

**国内网络**（FFmpeg 已改成镜像优先，决策 7.6；其余 2026-11-21 查的现状）
- 没有镜像：一键安装命令本身（`raw.githubusercontent.com`）和代码压缩包（github.com），这是第一步；Python（winget 从 python.org 下）；说话人模型（GitHub，约 40 MB，失败只提示）。
- 只在失败时换镜像、慢不换：pip、npm、Node.js。下载慢但没断时用户只能干等。
- 已经够用：转录模型（先探 huggingface.co，连不上用 hf-mirror.com）。
- 要做的：每一项都给国内来源，按「探一下原站，几秒连不上或明显慢就直接走镜像」统一处理；一键安装命令给一个国内能打开的地址写进 README 和 AGENT_INSTALL。

**卸载**
- 现状：两个系统都有分层卸载脚本（只卸程序 / 连模型 / 连数据，可先看要删什么，`-Yes` 免确认），README 有说明。
- 缺口：`AGENT_INSTALL.md` 没有卸载的说明，agent 不知道怎么替用户卸；装时注册到 Claude Code、Codex 的 FluentFlow 工具卸载时不删，删了程序后 agent 里会留一个打不开的工具；镜像下载的 FFmpeg 在数据目录，只卸程序时不删；代码目录要用户自己删。装进一个文件夹以后，卸载可以变成「停服务、注销工具、删桌面图标、删这个文件夹」。

## 朋友 Windows 安装更新全过程记录里查出的问题（2026-11-21，记录原件在王愉超的「下载」文件夹，未入库）

他朋友从 0.6.0 装起，手动更新过两次（跨约 290 和 103 个提交），全程靠自己的 agent 和本机代理。下面是安装会话那条之外的：
- **没有一条命令的更新**（挡住主要任务）：一键安装脚本碰到已有的代码文件夹只说「照 README 更新」，不升级；zip 装的要下新包、建新文件夹、手动复制 `.env`、删旧的；git 装的要自己 pull、装依赖、重建界面，更新到的是 main 不是发布版。产品里也不提示有新版本，AGENT_INSTALL 没有更新的说明。他朋友手动更新时漏了新版本要的讲话人模型。要做：一条命令（或页面上一个按钮）更新到最新发布版，保留 `.env` 和数据，补齐新依赖和模型，失败能退回旧版；页面提示有新版本；AGENT_INSTALL 加更新一节。
- **Windows 依赖不锁版本**（挡住主要任务）：av 19 发布后 faster-whisper 传的参数被删，Windows 上转录全部失败，直到加了 `av<19` 上限。Windows 没有锁定文件（只有 Apple 芯片 Mac 有），同类断裂还会再来。要做：Windows 也用实测过的锁定文件安装，CI 的 Windows 机器上验证；和「Python 依赖改用 uv」一起做。
- **代码文件夹挪了位置，Python 环境就坏**（让主要任务变差）：虚拟环境里写死了路径，他朋友挪到 D 盘后只能删掉重建。装进一个文件夹以后用户更可能整个挪。要做：启动器发现环境坏了就自动重建，或明确提示重跑安装脚本。
- **服务跟着窗口走**（让主要任务变差）：服务在一个黑色命令行窗口里跑，关了窗口服务就停；他朋友的 agent 在临时窗口里起服务，窗口被回收后误以为「服务掉线」。要做：服务在后台跑、不占一个要用户别关的窗口；AGENT_INSTALL 写明 agent 怎么起一个不随自己退出的服务、怎么查它活着。
- **本机代理不会自动用上**（只是没那么好）：他朋友开着本机代理，克隆和下载都要手动加代理参数。国内镜像做完后影响变小；可以让安装脚本读系统代理设置。

agent 绕开 FluentFlow 的 MCP 工具时记在这里（全局规则「绕了路就当场说，并记下来」），每周代码大扫除时汇总排序给王愉超挑。

- **实测没推的 MCP 或后端改动时，对话里连着的 MCP 工具用不上**（2026-11-25，字幕原地出笔记）：对话里的 FluentFlow 工具连的是 8000，跑的是主检出的旧代码；只好在 8013 起测试副本，用 Python 直接调 `scripts/fluentflow_mcp` 里的工具函数（设 `FLUENTFLOW_API_BASE` 和一个临时的 `FLUENTFLOW_ACCESS_TOKEN`）。另外 `prepare_test_copy.py` 打印的启动命令用本检出的 `.venv`，T3 开的 worktree 里没有它，要换成主检出的。改法：启动命令在本检出没有 `.venv` 时给主检出的解释器和临时令牌，并顺带打印一行「这样调工具函数」的示例。同一天「界面如实显示后台在做什么」实测撞上同一件事，改用 curl 调副本的 Agent API 和 `/jobs`，`.venv` 软链到主检出。

- **用测试副本看没推的页面改动，要另起一份检出**（2026-11-20）：测试副本的服务从本检出的 `frontend/dist-local` 发页面，开发服务器又只把请求发到 8000；8000 有任务在跑、又不能先构建（旧服务不认新选项），只好 `git worktree add` 一份、套上补丁、软链 `node_modules`、`.venv`、`.env`，在那里构建并起 8013。改法：让副本服务能从指定目录发页面，但先要让副本服务把页面的请求强制发回它自己（返回自己的页面配置）：页面的请求地址现在由配置和端口推断，副本起在 4173/5173/5186 上或用了写着 8000 的构建时，副本页面上的删除会落到 8000 的真实任务（2026-11-21 大扫除试做，推送前审查两轮拦下，决策 8.25）。
