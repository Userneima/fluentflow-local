## 任务「完成」指每一步都做完，被打断就从中断的那一步续上（2026-10-18 王愉超定）

- 起因：任务转录完就记为「已完成」，之后的剪辑判断、导出、写笔记还在同一次处理里跑。2026-10-18 16:50 另一个会话重启服务，剪辑被标为「重启中断」，写笔记没开始，任务停在有转录稿、没剪辑、没笔记，启动时的续接看到「已完成」就没管。为补这个「完成」的洞，已经各处打了补丁：agent 等任务另看「是不是还在剪」、删任务另看「笔记是不是还在写」、重启前检查另看剪辑状态。
- 要做：
  - 每个任务一张步骤清单（转录、剪辑、写笔记、整理文件夹），每步记「没开始 / 在做 / 做完 / 失败 / 跳过」，任务状态由清单算出：每一步都到了终点（做完、失败或跳过）才算完成。任务记录里已有一份步骤快照，在它上面改。
  - 某一步失败也算到了终点：显示「完成，但笔记失败」并给重做的入口，不让人和 agent 一直等。
  - 重启后续接从中断的那一步开始，跳过做完的步骤（不重转）；现在转录阶段被打断是整条重跑，一并改成按步骤续。
  - 转录稿一出来就能看，不等全部做完。
  - 每一步都能停下：现在取消只对转录中的任务有效（转录完任务已记为完成，取消返回 409），剪辑和写笔记阶段只能停掉服务。停下要做成「停掉这一步，以后从这一步续」：2026-10-17 手动冻住罗福莉访谈的导出进程，电脑睡了一觉，恢复后硬件编码直接报错退出，只能整条重跑。
  - 改完把上面那些补丁换成「看步骤清单」一处判断（agent 等待、删除、重启前检查都用它）。
- 范围：页面、agent 接口、队列里所有用到「已完成」的地方都要过一遍。
- 界面上先按真实结果标状态（2026-10-22，决策 6.23）：笔记没生成、只有转录稿、没去成气口、有剪辑待判断都不显示绿色「已完成」。后台状态和续接没动。

## 笔记在飞书存一份，两边自动同步（2026-10-21 王愉超定）

- 要什么：指定某篇笔记（或某个文件夹里的录像默认）在飞书也存一份；之后 Obsidian 里改了推到飞书，飞书里改了拉回本地，两边都改了以后改的为准，另一份另存在旁边。飞书那份只有王愉超一个人改。
- 做法：接在现有的飞书导出和「md 与 FluentFlow 互相同步」上，不另做 skill。第一次导出时记下对应的飞书文档，之后更新同一篇，不新建；本地改动沿用停下一分钟再同步；飞书那边定时看版本号，自己推上去的版本记下来，不当成飞书的改动。问题框、提示框转成飞书的高亮块，章节跳转链接转成飞书文档内的链接，截图上传。
- 先做备份再同步：每次覆盖任何一边之前，被覆盖的那一版先存一份，能找回。之后边用边改，不追求第一版就完美。本地这边已做（2026-10-21）：md 和任务里的笔记每次被覆盖前存进「过程文件/历史版本」，按时间命名、内容没变不重复存；飞书那份被覆盖前调同一个入口存成「飞书」版本，等同步做出来时接上。
- 往返实测（2026-10-21，罗福莉访谈笔记原样用 lark-cli 的 markdown 建文档再拉回，个人账号）：标题、列表（含嵌套编号）、加粗、普通引用、表格内容、正文全部回得来。回不来或变样的：
  - 问题框、提示框（`> [!question]`）进飞书只是普通引用，「[!question]」字样露在正文里；拉回时文字不丢，每行末尾多两个空格。要按计划先转成飞书高亮块。飞书高亮块拉回是 `<callout emoji="❓">` 标签，底色在 md 里丢掉，靠表情符号认回是哪种框。
  - 高亮块里不能放表格。笔记里有一个问题框下面挂了一张表，进飞书后表被挪到框外，拉回也在框外。
  - 章节跳转 `[[#标题|第五章]]` 在飞书里是一串不能点的文字。飞书的文内链接拉回是「文档网址#块编号」，要靠一张块编号到标题的对照表换回 `[[#标题|…]]`。
  - 分段写的笔记里那几行「第 1/3 部分」注释被飞书删掉；代码里只写不读，丢了没影响。
  - 截图拉回是飞书文件地址，不是本地图片，要在上传时记下文件编号对应哪张截图。
  - 表格分隔行、列表后的空行、行尾空格会被改写。判断飞书那边有没有改，要比两边整理过的形式，不能逐字比，否则每次拉回都像被改过。
- 推到飞书已做第一步（2026-10-21）：本机身份导出时问题框、提示框转成飞书高亮块（图标区分种类），框里的表格放到框后，表格保持表格，章节跳转链接指到飞书文档里的那一章；导出后任务里记下飞书文档、版本号、每张截图对应的飞书文件。罗福莉这篇实推核对过：12 个框、6 张表、跳转链接都对。
- 更新同一篇按章节（2026-10-21 王愉超定，已做）：只重写改过的章节，没改的章节原样留着（截图、飞书评论都在），改过的章节保留标题块，指向它的跳转不断。笔记改动停下一分钟自动推；再点导出也更新同一篇。更新前飞书那份存进历史版本，读不出来就不写。罗福莉测试文档实测：改一章只动了这一章，其余 486 个块没碰。
- 拉回本地（2026-10-21 王愉超定，已做；临时库里实测：飞书里给第三章加一句、插问题框、贴图，拉回后只有第三章变了，第二章的截图和折叠框原样，拉回后不推回去，之后本地再改只推那一章）。做法：每两分钟一次批量查所有同步中文档的飞书最后修改时间，比推送后记下的新、且停下一分钟才拉；每次推送后记下飞书那边每章的样子，拉回时只把飞书里改过的章节转回 Obsidian 写法换进笔记，没改的章节不碰；高亮块按图标认回问题框和提示框，文内链接换回 `[[#标题|文字]]`，原截图按文件编号换回本地图，飞书里新贴的图下载到截图文件夹；两边都改了以后改的为准，输的一份另存在 md 旁边；拉回前任务里的笔记存进历史版本，拉回后不再推回去；文档被删或没权限就停这篇的同步并写明原因，不重建。插截图改用一次性的临时标记定位，修掉图注编号重复插错位置的问题。转换的已知损失：飞书里改过的那一章，折叠提示框会变成不折叠；飞书里新建的、FluentFlow 没推过的章节，指向它的文内链接收回来仍是飞书网址。判断哪边后改：本地这边用服务运行中记下的改动时间，重启后退回笔记自己的编辑时间。没有标题的问题框（`> [!question]` 下面直接写正文）在飞书里那一章被改过后收回来，第一行会变成框的标题。
- 飞书那份的排版照 feishu-doc-ops 的笔记规则（2026-10-21 王愉超指出之前没照做）：框的标题是框里的四级标题、长段落首行缩进两格、正文块之间空一段、每章前分隔线、表格列宽贴文字加表头居中，收回本地时去掉。手动修一篇同步笔记的飞书那份时，先停掉 8000 服务再跑脚本：服务和脚本同时往同一篇写，内容会重复（10-21 罗福莉这篇出过一次，整篇重写后恢复）。

# 效率

## 记下每篇笔记真实花了多少、每段花了多久（2026-10-20 查出）

- 长录像分段写时，任务记录里的花费和耗时只是第一段的：合并各段时沿用了第一段的用量。罗福莉访谈（3 段）记的是 1.98 美元、写作 209 秒，实际写笔记这一步从 04:11:50 到 04:35:48 共约 24 分钟，三段各自的花费、查漏后补写的花费、查漏模型的花费都没记。
- 要做：每段的写作、查漏、补写分别记用量和起止时间，任务上给出合计；网页和 agent 看到的「这篇花了多少」用合计。订阅渠道写明这是按 API 价折算、计入订阅额度，不是另外扣钱。

## 长录像的转录原文载入慢（2026-10-22 实测）

- 现象：罗福莉访谈（3.5 小时、7104 句）打开编辑页，数据 0.6 秒取回，左边转录列表 12.5 秒才显示；第一次改字自动保存后再卡约 11 秒；播放和打字一顿一顿。处理记录页和 agent 页不慢。
- 原因（开发版页面、无头浏览器量的）：每句一个输入框，挂到页面时逐个量高度（`frontend/src/lib/format.js` 的 `autoSizeTextarea`，约 11.6 秒），每量一次浏览器重排整页；改字后 `resultKey` 变化触发全部重量；播放进度存在整个 `Editor` 组件上，每秒约 4 次整页重画；打字每个键重画全部行。
- 方案：A. 输入框高度交给 CSS `field-sizing: content`，Firefox 一次量完所有高度，去掉改字后的重量，约 1–2 小时，试改后 12.5 秒降到 1.1 秒（行高没核）；B. 播放进度放进单独的小组件，行做成 memo 组件，只重画变化的那一句，约半天到一天；C. 只渲染屏幕上看得见的行，约 1–2 天，Cmd+F 搜不到屏幕外的句子；D. 任务接口不再带四份没用的字幕副本，收益小。倾向先做 A 加 B，做完还超过 1 秒再考虑 C。
- 做完的标准：这条任务的转录列表 2 秒内出来，第一次改字后不卡，打字和播放不明显卡，行高正确，前端 lint、build、test 通过。测量只发读请求，不往这条任务写东西。和编辑器换成 Obsidian 式都改 `editor.jsx`，先后做。


## 第三批：剪辑判断和写笔记合成一次读（2026-10-18 记）

- 现在只用网页、FluentFlow 自己调模型时，同一份转录稿被读两遍：判断剪辑读原片转录稿和约 24 张空白截图，写笔记读剪后转录稿和几十张截图。合成一次：读一遍原片转录稿和截图，先定剪辑，再按剪后剩下的内容写笔记，一起交回；笔记也不用等导出完才开始。
- 先在第一批的质量考题上比新旧两版，笔记没变差才合并（同一次请求里多一件事，笔记可能写得不如现在）。省下的是重读一遍转录稿的那部分，不是一半。
- 用户自己的 agent 那条路天然只读一遍（第二批），不受影响。
- 顺带：截图现在按画面变化先抽一大批再交给模型（张和 2 号那条抽了 73 张，笔记只用了 2 张），合成一次读后改成只截理解里标出的那几个时刻。
