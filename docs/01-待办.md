# 效率与方便

## 第三批：各步只写自己那一格，导出和写笔记同时跑（2026-10-16）

- 现在一个任务的结果存成一整份，导出、整理处理说明、写笔记每一步都「整份取出、改自己那部分、整份放回」，两步同时跑时后放回的会把先放回的冲掉，所以靠「禁止同时跑」防丢数据。
- 做法：加一个只改记录里指定几项的写法（数据库支持），这三步改用它，各写各的那一格。之后导出视频和写笔记可以同时进行，长录像每条约省 6 分钟（张和 58 分钟那条估算：等 Claude 写正文的 6.5 分钟可以和导出重叠），也不再靠一条禁令防丢数据。
- 排在第二批之后：第二批会改变剪辑结果，这一条只影响快慢。重新导出一次只受理一个，已单独修好（决策记录 2.11）。

# 等前提

前提出现之前不做（2026-10-15 按投产比收缩，见决策记录 8.5）。

**对外发布时**（现在只有王愉超自己用）
- **实机安装**：Windows 按改过的脚本（Python 只装给当前用户、Node.js 用免安装版、下载失败换镜像）实装一次，并核实 winget 会不会弹管理员授权；全新 Mac 实装一次，确认全程没有要人点或输入的地方。
- **干净 agent 走一遍完整流程**：照 `AGENT_INSTALL.md` 安装 → 替用户写一篇笔记 → 收到截图反馈后「验证 → 加规则」。两个方案（[让 agent 替用户安装](方案/2026-10-11-让agent替用户安装.md)、[笔记交互搬进 agent 对话](方案/2026-10-11-笔记交互搬进agent对话.md)）都还差这一步。
- **第一次填 Key 引导里给出费用估算**：要先在写笔记时记下每次用了多少 token，再按官方单价算。
- **双击安装包**（打包 Python、转写模型和前端，签名后直接双击安装）：工程量大，走通 agent 安装后再看普通用户还缺不缺这条路。

**攒到真实记录时**
- **agent 改笔记时只交回改过的部分**：现在改一个字也要整篇交回，可能顺手改了别处。按节交回还是按一句原文定位替换，看 agent 实际修笔记时最常改的是什么再选；3 万字以上的笔记连同任务包会超过 Claude Code 一次能收的大小，到时一并处理。
- **新剪辑流程的反馈第 2、3 层**：规则规定必须问的类别设毕业条件；用户反复纠正同一类时起草剪辑规则。等攒到真实点击再定门槛。
- **拿不准的剪辑判断给模型看截图**：实测里出现「画面关键却被剪掉」或理由和画面对不上，再给拿不准的几段各截几张图。
