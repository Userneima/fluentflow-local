# 可靠


## 自选位置又只在 `.env` 里改了端口时，不带位置的安装命令可能另装一份（2026-11-27 交付推送审查的建议）

`install.sh` ~242、`install.ps1` ~418 找正在运行的安装时，端口只看环境变量或默认 8000，不读安装目录里的 `.env`（还不知道安装目录在哪）。装在自选位置、端口只写在 `.env` 的，再跑不带位置的安装命令会找不到在跑的服务，在默认位置另装一份。改法：页面给的更新命令本来就带位置和端口（7.14）；裸命令找不到时，再按常见位置读一次 `.env` 的端口，或在提示里说清要带 `FLUENTFLOW_INSTALL_DIR`。

## 安装给 agent 注册工具的三处小缺口（2026-11-27 交付审查的建议，不挡交付）

- 带注释的 `opencode.jsonc`（OpenCode 自己能读）现在不自动注册，只打印要合进去的那段；要自动写得先能保留注释地改 JSONC。卸载也一样：这种文件里的条目卸载时既不删也不提醒（脚本退出码 2 被当成「没有要删的」），文件夹删掉后 OpenCode 里留下一条失效注册；至少要提醒手动删（Mac、Windows 两份卸载）。
- 端口变了重新注册时，Claude Code 和 Codex 是先注销再注册，用户在我们那条上加的设置（Codex 的 `startup_timeout_sec`、工具审批，Claude Code 里多加的环境变量）会丢，Claude Code 的条目还会从项目作用域变成用户作用域；改成就地只改地址。
- `uninstall-local.ps1` 在没有 `.venv` 时什么也不说（Mac 那份会提示）；Mac 卸载的兜底 `grep` 只看 `opencode.json`、不看 `opencode.jsonc`；`opencode_mcp_config.py` 参数写错时也退出码 2，安装会当成「有意不动」；写不进配置时打出 Python 报错栈，不是一句人话。

## 排队前那段等待里按的停下，接着做的任务还会丢（2026-11-27 第二轮审查建议，不挡交付）

- `task_queue._start_behind_queue` 先等一次读写步骤再登记 runner。之前停过的任务，它的停止事件要等新一轮 `task_stop.begin` 才清，所以接着做（`resume_subtitle_in_place` 这类）时「占位前已在停止」是真，用户在这段等待里按停下会被放过，runner 起来后 `begin` 把这次停下清掉，笔记照常写完。步骤还没落盘时按停止，`task_actions.stop_step` 看到没有开着的步骤、runner 也没起，会直接拒绝。
- 改法：`_start_behind_queue` 开头先 `task_stop.begin(task_id)`，之后只看 `task_stop.requested`；排队中的任务也接住停止请求。这条分支返回时 `resume_task` 报的是「已经在处理了」，另给一个「已停下」的回复。补「步骤还没写就按停止」的测试。
