# FluentFlow Local Changelog

## Unreleased

- 结合画面写的笔记在替换现有笔记之前先过一道检查。标题前面混进的杂字（比如「： #」「deep#」，或标题上方「好的，这是……的笔记。」这类开场白）会被去掉，正文不动。录像不短、笔记却短得不像样（比如只有「ewline placeholder」）时，自动重写一次；还是不行就报失败，原来的笔记保留不动。
- 英文录像在没有 DeepSeek、OpenAI、通义 Key 的机器上也有中文字幕：翻译改由写笔记用的 Claude（你的 Anthropic API Key，或开启了的本机 Claude 订阅）来做。两样都没有时照旧提示去填 Key。
- 任务记录页打开更快：列表不再读出每个任务的全部转写分段和笔记全文。重启前检查进行中任务的脚本等待时间放宽到 10 秒，转写正忙时不会再报「无法判断」。
- 链接任务完成后不再删掉下载下来的原片。此前任务一完成，清理链接临时文件的那一步会删到任务自己的那份视频；去气口被判为不该剪、转写用的是原片时，笔记就因为找不到录音而写不出来（2026-10-09 稳定性实测中的 B 站视频）。
- 第一次打开时，如果还没有能写笔记的模型，首页会出现一张引导卡片：说明 API Key 是什么、推荐先用哪家、去哪里申请、怎么计费；填好后会先检查这个 Key 能不能用再保存。之后随时能从首页提示条或设置页「笔记」里再打开。
- 局域网里的其他设备填过访问令牌后，笔记里的截图也能正常显示；没填令牌时页面直接说明要去「菜单 → Agent 接入」填写。「关于」页的局域网说明同步改为需要令牌。
- 任务状态和说明不再误导人。链接下载的进度单独显示，不再写进笔记状态，转写时也不会还挂着「正在保存视频信息」；「AI 笔记生成」一步写明谁根据什么写的笔记（Claude 读了去气口后的版本或原录音的画面和转录稿，或文本模型根据转录稿），重试后还没下载的链接任务不再显示「素材已保存」；任务详情按事件记录标出真实发生过的步骤和时间；材料判断全用中文，30 分钟以下的录音不再叫长视频；去气口剪辑表、去气口成品、图文笔记有了中文名称。笔记读的是原录音时，任务记下的来源是 `source_media_note`，不再写成剪后版本，接口另给 `note_from_frames` 说明是不是 Claude 结合画面写的。改由文本模型写的笔记，任务卡片和编辑器会说明原因；编辑器空状态和设置页「笔记」一栏的说法统一，首页把已取消的任务标成「已取消」，自动导出飞书的结果不用重开任务就能看到，中文界面去掉了残留的英文和行话，「抖音备用解析」成了单独一项，导出记录也列出自动导出的文档。「关于」页和 README 写清了图文笔记会发送转录稿和画面、飞书默认以本人身份导出、局域网模式下同网段的人不带令牌也能读到全部转录稿和笔记、只该在可信网络开启。AI 工具按路径或链接提交时，讲话人区分用同一个默认：本机装了 pyannote 才默认开启。MCP `submit_transcript` 改为立刻返回任务编号、后台写笔记，用 `wait_task` 等结果，传入的笔记模式和提示词会交给模型；各提交工具写明笔记模式和提示词只在文本模型写笔记时生效，`write_note_from_cut_media`、`debreath_task`、`retry_task` 的说明与实际行为一致；`scripts/check_mcp_server.py --backend-e2e` 核对全部工具并走一遍提交到读取，「Agent 接入」页给出的命令和配置用本机真实路径。维护文档写明图文笔记默认用你自己的 Anthropic API Key、本机 Claude 订阅要设 `FLUENTFLOW_VISUAL_NOTE_CHANNEL=subscription` 才启用，`FLUENTFLOW_LOCAL_AUTO_NOTE` 关掉后仍会用文本模型写笔记，环境变量表补上 `FLUENTFLOW_NOTE_DEADLINE_SECONDS`，并有测试保证代码读的每个变量都在表里。
- 「重生笔记」按任务判断：这个任务能让 Claude 结合画面重写就照旧，不能时说明原因并改用文本模型；由 Claude 写笔记时也多一个「改用文本模型按文字重写」，「更换提示词」由此真正起作用。笔记正在重写时先等它写完。从系统对话框选文件和处理整个文件夹时，带上和上传完全相同的设置。同一链接正在处理时不会重复提交；已经处理过的会先问一句再处理。
- 处理结果更守设置，不再重复干活、不再丢笔记。从系统对话框选的文件和整个文件夹，后端现在接受和拖进来上传完全一样的设置（服务商和模型、提示词、笔记模式、自动配图、自动导出飞书及其路线和文件夹、标题），存下的任务设置与上传的一模一样。重试链接任务时，浏览器登录和抖音备用解析按你现在的设置来，关掉备用解析后重试不会再把链接发给第三方。`FLUENTFLOW_SOURCE_RETENTION_DAYS=0` 真的不再清理原片，此前任务一完成就把原片删了。同一条链接（只差跟踪参数也算）正在排队或处理时再提交，直接回到那条任务，不再下载第二遍；已经处理完的会返回 409 `duplicate_link`，带上 `allow_duplicate: true` 才再处理一次，失败或取消过的不受影响，MCP `submit_video_link` 加了这个参数。MCP `regenerate_note` 遇到 Claude 结合画面写的笔记时，能跑就照编辑器的做法重新结合画面写，否则用文本模型按传入的或任务原来的提示词和笔记模式写；旧笔记都会保留、可以免费恢复；重写失败时任务仍是已完成，只在笔记状态里写明失败原因。
- 设置和同意说了算。抖音备用解析改成先问再用：网页第一次提交抖音链接前问一次并记下选择，之后在设置里的「抖音备用解析」随时可改；没选过时不把链接发给第三方，需要它的链接会失败并提示去设置里允许（诊断代码 `douyin_fallback_not_allowed`，允许后可直接重试），重试按当前设置，MCP `submit_video_link` 加了 `allow_miuistore` 参数。飞书导出路线和文件夹存进服务的偏好（`lark_export_route`、`lark_folder_token`），MCP `export_result` 不再固定走飞书应用路线，按请求、设置、自动的顺序选，判断 lark-cli 是否登录不再卡住服务，导出的链接也出现在编辑器里。Claude 不可用、改由文本模型写笔记时，保留你的提示词、笔记模式和说话人标注，并生成可下载的笔记文件。自动剪辑被放弃后手动剪过的任务，可以再剪；手动重剪渲染失败时，剪辑表和字幕保持上一次成功的版本，和保留下来的剪后文件对得上。设置页在没填 Anthropic Key 时也显示「给笔记自动配图」和千问 Key；只填了 Anthropic Key 时，「字幕生成笔记」会提示拿不到笔记，不再静默失败。

- 从链接下载的视频只在任务里留一份：下载完放进任务目录，确认大小一致后删掉下载目录里那份；以前的任务在下次清理时也会删掉多出来的那份，大小对不上的不动。重剪改为先渲染到临时文件、成功后再替换，渲染失败时原来的剪后文件和任务记录都保持原样，放在原文件旁、与它是同一个文件的那份也不会被改写。服务被强杀后，下次启动会删掉链接下载留下的隐藏临时目录，并停掉还在后台下载的 yt-dlp，只停命令行对得上的那个进程。局域网模式下，其他设备查看也要带访问令牌，没带时提示到那台设备的「菜单 → Agent 接入」填入，只有页面本身不需要；`.local` 来源只认这台电脑自己的名字。链接任务的事件记录不再写那个打不开的 `/video-sources/files/…` 地址。

## 0.6.0 - 2026-10-08

- 批量处理和笔记更稳，任务显示更准。笔记等 Claude 回复时改在自己的线程里等，一批短录音不再占满上传和转写要用的线程；在笔记等名额或已在写时取消任务，名额都会还回来，不会越用越少。写笔记超过总时限时，已经写好的初稿保留为笔记，只跳过统一文风和覆盖率修订，任务里记下 `deadline_hit`；还没有初稿时才报超时。笔记还在写时，任务步骤里的「AI 笔记生成」显示为进行中；转写完成后记录写明转写完毕和全长；排队提交返回的是在整条队列里的真实位置；事件记录写明任务从哪个入口提交，纯音频任务记为 `audio`。同一个任务的笔记正在写时，手动去气口会被拒绝并说明原因；转写时已经去过气口的任务不能再剪一次，会提示重新提交原文件，避免字幕和笔记的时间点对不上。重复提交一个正在运行的任务不会再让后面的任务插队。局域网模式下，在其他设备上打开的页面填好访问令牌（「菜单 → Agent 接入」）就能提交和修改，没有令牌时提示只能查看，README 写明了怎么开。在原文件旁交付的剪后文件和任务里那份在同一块磁盘上时是同一个文件，不再占两份空间，删掉任意一份另一份照常可用。`distribution/local.env.example` 去掉了不再起作用的设置项。
- 下载 Markdown 笔记时，带截图的笔记改为下载一个压缩包：里面是笔记和 images 文件夹，截图链接指向文件夹里的图片，在 Obsidian、Typora 里直接能看；没取到的截图保留本应用的完整地址，提示里写明张数。没有截图的笔记仍是单个 .md。导出 Word 时截图按原比例缩放，竖屏截图不再被压成 16:9。由 Claude 结合画面写笔记时，「更换提示词」按钮和提示词窗口会说明提示词和笔记模式只在改用文本模型重生时生效。转录稿来自剪后文件时，字幕下载项标明「对应剪后视频」、文件名带「_剪后版」，菜单里多一项剪后视频下载，原视频一项标明与字幕时间对不上。
- 飞书导出保留笔记里的截图，失败时说得出原因。本机身份导出（lark-cli）改用 lark-cli 现行的创建命令（旧参数已被 lark-cli 停用，此前这条路线建不出文档），文档建好后把每张截图插回原来的位置，截图下方留一行「图 N：说明」；应用导出遇到带本机截图的笔记时改用会上传图片的写法。有截图没传上去时，导出提示写明张数，不再只说「导出请求已发送」。失败原因分开说明：没装或没登录 lark-cli、缺哪项权限（写出权限名和补授权命令）、没填或填错 App ID / App Secret、找不到文件夹、请求太频繁；lark-cli 自己给出的中文说明原样带上，提示里的设置项名称改成现在的「飞书导出路线」。手动导出的文档链接记在任务里，再打开任务时导出按钮旁显示「已导出 · 打开」，再导出一次会先确认；自动导出失败时编辑器里会显示原因。新用户默认「自动选择」：本机装了并登录了 lark-cli 就以本人身份写进「我的文档库」，否则用飞书应用导出；应用导出可以在设置里填飞书文件夹链接，文档建在那里。分批写入中途失败时，提示里给出已建好的半截文档链接。
- 重试失败的链接任务时带上当前的浏览器登录设置和原来的全部选项，长分享文本里的链接不会再丢；读不到登录、图文、会员内容、超过大小或时长上限这些重试没用的失败，不再显示「重新提交」。设置页的浏览器登录态改存在服务里，AI 工具提交的链接也会用它；新增「抖音备用解析」开关。链接框改叫「视频链接」。下载进度拿不到百分比时显示已下载多少，不再停在 10%。
- 负责下载视频的组件每天启动时自动检查更新一次，平台改版后不用重装就能跟上。
- 从链接获取视频更稳，失败时说得出原因。浏览器登录态读不到时，B 站、YouTube、抖音都改为不带登录继续下载，不再整批失败；B 站和 YouTube 交给下载工具自己下载并合并音视频，最高 720p，此前 B 站普通视频常常下不下来；抖音下载被转到合作 CDN 时不再被拒，用下载工具解析成功但下载失败时会重试并改走第三方解析。B 站会员内容只拿到试看片段时直接说明，不再当作完整视频处理。抖音图文作品、已删除或私密的视频，YouTube 的机器人验证、年龄限制、私享视频，B 站需要登录或已删除，各自给出对应的提示，只在确实是登录的问题时才提登录；重试解决不了的失败不再建议「重试一次」。链接后面紧跟的中文不会再被当成链接的一部分，`iesdouyin.com`、`bili2233.cn`、不带 `https://` 的短链都能识别，粘了多个链接时会提示只处理了第一个。下载中断不会留下半截文件被下次当成完整视频，同一链接同时提交两次只下载一次。链接下载的大小上限改成和本地上传一样，超过大小或时长上限时在下载前就说明实际大小和上限。同时最多下载两条链接，下载进度会按百分比走。下载阶段就失败的链接任务可以直接重试，会重新下载这条链接。浏览器登录态的选择存在本机服务里，AI 工具提交的链接也会用上。抖音标题去掉了末尾的话题标签，直链用文件名做标题。
- 抖音链接又能直接下载了。第三方解析服务改了页面，结果改由页面里的脚本再加载一次，此前我们只读到一个空页面，所有抖音链接都报「暂时无法自动解析」。另外，配了浏览器登录态但读不到（例如 macOS 27 不允许其他程序读取 Chrome 的数据）或已过期时，不再跳过第三方解析；两条路都失败时，提示会说明是读不到浏览器数据还是登录过期，以及怎么处理。
- 用链接提交的任务也会自动写笔记；此前链接任务跳过了文字笔记，又没有接上结合画面的笔记，最后一份笔记都没有。
- 开了「自动导出到飞书」时，转写后自动写的笔记也会导出，任务里记下文档链接或失败原因；此前这类任务一直停在「等待飞书导出」。
- 「重生笔记」按当前写笔记的方式来：由 Claude 写笔记时，重新结合画面来写；由文本模型写时，确认框会说明用哪个模型，并提醒原来笔记里的截图不会保留。
- 笔记还在写时打开任务，页面会自己刷新出写好的笔记或失败原因，不用退回列表再点进来。
- AI 工具（MCP）等待任务时，会等到笔记写完才返回，并说明笔记写成、失败还是不需要；各工具的说明改成现在的自动流程。
- 提交之后 Claude 用不了（Anthropic API Key 被删或失效；选用本机订阅通道时还包括登录过期），任务会改用文本模型写笔记，没有文本模型 Key 时写明原因；此前这类任务静默地没有笔记。
- 服务在笔记刚标记「正在写」、还没真正开始时重启，启动后会把它标成失败并说明重写即可，不再一直显示「正在写」。
- 任务产出的东西不再自动删除。转写稿、笔记、字幕、截图和去掉气口的音视频都一直保留，直到你自己删掉这条任务；唯一自动清理的是 FluentFlow 另存的原片：上传文件的副本 7 天后清理；从链接下载的视频只有在已经生成去气口版本时才在 7 天后清理，否则一直保留，因为它是这段录像唯一的一份。此前 30 天没有改动的任务会连同笔记被整条删除，而且没有任何提示。
- 事件记录补上了几个此前看不到的环节：排队等了多久、去气口用时和剪掉多少、结合画面的笔记写没写成和用时、因 Claude 用不了而改写文字笔记的任务、被服务重启打断的任务。转写记录里的「模型加载时间」改为只算加载本身，此前把第一段转写的时间也算了进去。
- 一批任务里，上一条录音的笔记在等 Claude 回复时，下一条录音就开始转写，不再干等笔记写完。笔记从视频里挑截图的那一步仍然和其他本机处理轮流进行；同时等 Claude 回复的笔记不超过两份。
- 选用本机 Claude 订阅写笔记（`FLUENTFLOW_VISUAL_NOTE_CHANNEL=subscription`）时，本机 Claude 登录过期，首页和设置页会直接说明，并告诉你在终端运行 `claude` 重新登录。这期间提交的任务会改用你设置的文本模型写纯文字笔记；此前这类任务转写完才发现登录失效，而且文字笔记也被跳过，最后一份笔记都没有。
## 0.5.0 - 2026-10-06

- 失败原因改成能照着做的中文：AI 服务拒绝 API Key（含 DeepSeek 的说法）或限流时说明是哪种情况、下一步做什么；飞书导出找不到目标文件夹时报的是文件夹而不是任务；视频平台拒绝下载时如实说是平台拒绝，提示开启浏览器登录态；一次提交的文件超过上限时写明上限并建议分批，页面在上传前就会拦下；重试一个原始录音已被保留策略清理的任务时说明要重新添加文件。笔记导出到飞书时行内代码按代码样式导出，不再带反引号。
- 导出的 SRT/VTT 字幕时间戳毫秒进位正确（此前 1.9995 秒会写成 1 秒 1000 毫秒，播放器不认），编辑器里清空的句子不再导出成空字幕，下载文件名里文件系统不接受的字符换成空格。
- 首页拖文件上传、贴视频链接、重试任务都排进同一条队列，一次只处理一个；此前这几条路会和排队中的任务同时开跑，两个 ffmpeg 一起渲染会把内存挤爆、速度掉到十分之一。队列忙时手动去气口和画面笔记会提示稍后再试。
- 手动点「去气口」时也按这段素材实测静音阈值，不再把默认阈值当成你指定的值；做过响度处理的录音此前会剪掉 0% 并显示成功。任务记录里写明用了哪个阈值。
- 去气口过程中 ffmpeg 解码失败或超时，任务改用原文件继续转写并记下原因，不再把「解码失败」当成「没有气口可剪」。
- 剪后的文件统一输出为 mp4 或 m4a；此前 webm、ogg、flac 这些来源会在渲染第一段时失败，mkv 来源总是通不过自检。
- 视频链接下载到一半失败或被取消时清掉残缺文件；此前同一链接再提交会把残缺文件当成已下载的完整视频去转写。取消时连带结束下载器拉起的子进程。
- 重新生成笔记时模型没有返回内容，保留之前的笔记并说明原因，不再用空笔记盖掉原来的。
- 笔记修订环节输出为空或明显短于初稿时保留初稿，不再把截短的版本当成最终稿。
- 转录稿太长时截图规划只读到某个时间点，任务记录里写明之后的内容没有配图；此前后半段没有截图也不说明。
- 设置里选 deepseek-chat 就用 deepseek-chat；此前前后端都会悄悄改成 deepseek-reasoner，更贵更慢。
- 写笔记的每次模型请求有超时，整个写笔记过程有总时限（默认一小时，`FLUENTFLOW_NOTE_DEADLINE_SECONDS` 可调），不再因为一个请求挂住而让任务停在「写笔记」不动。
- 本机服务没有响应时，页面顶部显示提示并暂时禁用提交，不再只在角落显示英文的「Failed to fetch」。
- 任务失败原因不再出现「需要重新登录」这类托管版的说法：API Key 失效的提示直接指向设置页，并写明是哪家服务；只有视频链接任务的超时才会建议改传本地文件。
- 首页提示、批量确认框和设置页用同一句话说明当前由哪个服务写笔记，此前三处说法互相矛盾。
- 处理记录页只重绘有变化的卡片，长转录稿逐字编辑不再每敲一个字就重绘整页。
- 弹出菜单和对话框支持 Esc 关闭和键盘焦点，笔记里的图片说明不再能注入页面脚本。
- 处理完成的任务不再把完整结果一直留在服务内存里，连续处理几十个讲座后内存不再只能靠重启释放。
- 局域网访问模式（`FLUENTFLOW_ALLOW_NON_LOOPBACK`）下写操作必须带访问令牌，网页跨站请求仍被拒绝。
- 服务启动时也会判断转录模型的下载源：连不上 huggingface.co 就改用镜像。此前只有安装脚本会这样做，安装时没下成模型的机器，第一个任务会一直等在连不上的主站上。
- macOS 安装脚本下载模型失败时会停下来说明怎么补，不再把「安装完成」和一个没有模型的环境一起交给你。
- 再次双击桌面上的「FluentFlow Local」时，对话框里多了「停止服务」；有任务在处理时会先问。
- 桌面启动器读 `.env` 里的 `FLUENTFLOW_LOCAL_PORT`，改端口不用再改环境变量。
- 启动器的日志超过 5 MB 时自动换一份，不再无限增长。
- Windows 安装脚本装完 FFmpeg 后立刻确认能找到它，找不到就停在那里说明，而不是装完全部依赖后才在就绪检查里报错。
- Apple 芯片 Mac 的 Python 依赖按实测过的锁定文件安装；版本号只写在 `VERSION` 一处。
- AI 工具调用接口被拒绝（401）时，提示直接说去核对 `.env` 和 MCP 客户端配置里的令牌是否一致。
- README 补上什么内容会离开这台电脑（抖音链接的第三方解析及关闭方法、浏览器登录态的钥匙串授权）、怎么停止服务、zip 安装后怎么处理旧文件夹、国内 pip/npm 镜像；`docs/maintenance.md` 列出每个环境变量。

- 文件名是「5.投资人视角下的AI浪潮」这种「编号.标题」格式时，任务标题和下载文件名不再被截成「5」。已经存下的标题在服务启动时改回完整的。
- 处理记录卡片上的笔记字数改为笔记的真实长度，此前超过 240 字的笔记一律显示「240 字」。
- 在 Mac 上转写时，录音的语言按各段说话时长多数决定，不再只看第一段。此前片头音乐会让中文讲座被判成英文，接着被送去翻译，转写稿开头还会多出一句「Thank you.」。
- 本机 Claude 登录过期时，笔记失败的提示直接说明要重新登录，不再显示英文原始报错。
- 设置页的飞书导出说明改为本地版实际的用法；去掉「清除本地历史记录」，它只清浏览器缓存，刷新后记录就回来了。
- 这台电脑没装讲话人区分组件时，任务直接跳过这一步并说明原因，不再每次记一条失败。AI 工具提交任务时不再默认要求讲话人区分。
- 服务关闭时一并停掉还在写笔记的 Claude 进程，不再让它在后台继续消耗额度。
- macOS 上有任务在排队或处理时，电脑不会因为闲置自动睡眠，全部做完后恢复正常。此前一批任务交给它就离开，电脑睡着后任务只在系统每隔一刻钟短暂醒来时往前挪一点，16 分钟的录音用了 69 分钟。合上盖子、手动睡眠和低电量仍然会让电脑睡。
- 用本机 Claude 写笔记时如果连接中途断开或服务暂时过载，会等几秒自动重试一次；登录失效和额度用完不重试，直接说明原因。
- 服务重启时正在排队或处理中的任务，启动后自动按原顺序重新排队，不再只标成失败等你手动重试。原文件已经不在的、或者连续两次处理到一半都被重启打断的，仍然留在启动后的提醒里由你决定。
- 手动重试一个任务时，它会排进队列等前面的任务做完，做完转录后也会接着写笔记。此前从 FluentFlow 保存的副本重试时，任务会立刻和正在跑的任务同时处理，而且只出转录稿、不写笔记。
- 设置页最上面新增「笔记」一栏：先填文本模型的 API Key（默认 DeepSeek），可选再填 Anthropic API Key 让笔记结合画面来写，每个 Key 旁边都有创建入口。此前文本模型 Key 收在折叠区里，Anthropic Key 只能写进 `.env`。
- 首页在没有任何可用的模型 Key 时显示提示条，说明这次只会得到转录稿和字幕，并给出去设置的入口。
- Windows 安装脚本缺 Python 或 Node.js 时用 winget 直接装上，并检查 Python 不低于 3.10。
- README 补上机器要求、不用 git 的安装方式、第一次使用、飞书导出、AI 工具接入、更新和排错。
