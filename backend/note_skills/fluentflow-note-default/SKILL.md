# 写一份录像笔记

笔记是一条学习路径，读者以后打开它，要能很快想起主旨、看懂概念、分清相近的概念，并能顺着它继续追问。

## 准确

- 只写能从转录文字或截图里确认的内容。背景知识、推测不写成讲者说过的话。
- 分清讲者的观点和笔记自己的推论。自己从例子里推出来的结论标「我的理解」，只写一处。
- 保留讲者的限定词。讲者说「往往更好」就写「往往更好」，说「至少 100 条」就写「至少 100 条」。
- 评价要有出处。「为什么值得看」写具体能学到什么。
- 同一个词在整篇里只指一样东西；讲者用一个词指两样东西时，笔记里换成两个词。
- 简化讲解时写明简化的边界，让读者知道哪里是近似。

## 转录稿的错

- 纯粹的语音识别错字，以及截图上能看到正确写法的名字和数字，正文直接写对的写法。
- 转录稿和截图都定不下来、靠猜的人名、机构名、产品名和数字，写进笔记末尾的「存疑」一节，逐条说明转录稿里是什么、填了什么、依据是什么，或者说明没有填。没有这类内容时不写这一节。
- 版本号、百分比、金额、日期、人名在转录稿里有互相冲突的说法时，正文写明「有冲突，请回听确认」，列出几种说法和各自的时间点。
- 去掉口头语和无意义的重复，保留理解所需的具体例子、步骤、数字和限制条件。

## 画面

- 画面用来补口播里没有的信息：一个具体的数字、一个命令、被说错或含糊带过的名字、图表体现的结构关系。把它写进正文的叙述，跟口播内容并列。配置项、清单、代码、表格这类原文从画面抄。
- 这一屏的内容口播已经完整说过，就不引用、不复述。
- 幻灯片、板书、代码、公式、图表、界面演示、实物演示本身需要看的，引用那张截图。图注一句话，写出点开会看到什么，比如「部署前的坑清单模板」。屏幕上的文字写进正文，图注只负责指路。
- 引用几张由内容决定，可以一张都不引用。片头、片尾、过渡、纯人像、和前一张几乎一样的画面跳过。
- 录像里展示一份文档（讲义、PDF、网页、幻灯片）时，笔记开头指向那份文档。正文记录讲者对它说了什么：口头讲的方法、判断、取舍和现场问答；文档里讲者没有讨论的部分，留给读者去看原文。

## 解释

- 术语在正文第一次出现的地方用括号解释，比如「运行记录（transcript，一次运行的完整记录）」。图注里出现不算第一次。以后在别处还会碰到的英文术语，保留英文并附中文。术语解释都放在正文里，笔记不另设词汇表。
- 解释一个机制时写「它怎么运作 + 一个例子 + 适用边界」。抽象的机制用动作词说，比如「寻找」「压缩」「预测」「校正」。
- 容易混淆的概念放在一起辨析。
- 类比只在能讲清机制时用，并且准确。

## 结构

- 先看材料本身怎么讲，再定笔记结构。课程讲座常按「问题、概念、机制、例子、边界」；教程操作常按「目标、前置条件、步骤、关键参数、常见错误」；访谈和讨论常按「议题、观点、依据、分歧」。选能让人重读的最小结构。
- 笔记第一行是一个一级标题，写这段录像的主题；正文的节用二级标题，节里再分用三级标题。标题来自内容本身的主题。内容多的节分层级标题，步骤类内容每一步一个小标题；短的节保持一层。小标签升成标题后，正文里不再重复那个标签。
- 案例放在它支撑的观点旁边。
- 同一个意思只写一处。写完通读一遍，看同一个结论有没有在几节里重复出现，有就合并到最合适的那一处。
- 一节开头可以先用一句话给出答案，再展开。
- 短标签加粗放在冒号前，比如「**作用**：」；强调只给关键词、概念名和关键区别。
- 表格只用于天然适合对比、清单、参数的内容，用标准 Markdown 表格。代码块只放真实的代码、命令和配置。
- 长的笔记结尾有一节回顾，标题下面直接列条目：定义、机制、边界、用法各一两条。
- 出处信息放在末尾。

## 只写内容

笔记里只写录像讲的内容。音质、杂音、用了哪个模型、处理过程这类说明写进 basis_note。

用中文写。
